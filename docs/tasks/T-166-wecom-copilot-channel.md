# T-166 企业微信 Copilot 渠道

**版本**：V0.5（运行时架构 v2）　**依赖**：T-041、T-028　**PRD**：原 PRD 渠道章节；演进 PRD 23.5；`architecture-runtime-v2.md`

## 目标

员工在企业微信里直接和智能体对话（Copilot）。作为一种新的渠道类型接入 T-041 的渠道框架，复用开放对话 API 的运行入口。

## 范围

1. **渠道类型 `wecom`**：实例配置——企业 ID（corpid）、应用 AgentId、应用 Secret、回调 Token 与 EncodingAESKey；密钥加密存储、响应只返回掩码；发布快照与回调地址沿用 T-041。
2. **回调**：企业微信“接收消息”回调的签名校验（`msg_signature` + 时间戳 + nonce）、AES 解密、`echostr` 校验；防重放（`MsgId` 去重）、限流；回调必须在企业微信要求的时间内应答，运行异步进行，结果通过**主动发送消息**接口回复。
3. **消息**：文本；长回复按企业微信长度上限切分；暂不处理图片 / 语音 / 文件（回复“暂不支持该类型”）；终端用户标识 = 企业微信 userid（`channel_type=wecom`），与 T-095 的企业微信成员打通时可关联到租户成员。
4. **访问令牌**：`access_token` 获取与缓存（到期前刷新），失败重试与告警。
5. **渠道体验**：沿用 T-042 / T-043 的体验继承；企业微信不支持流式，回复为最终文本；欢迎语与菜单（可选）。
6. 前端：渠道向导中新增企业微信类型（配置项、回调地址与校验步骤、测试消息）。

## 验收标准

- [ ] 测试：签名校验（通过 / 篡改 / 过期）、解密、`echostr`、`MsgId` 去重、限流、长回复切分、`access_token` 缓存与刷新、凭据只有掩码、跨租户 404、权限 403。
- [ ] 契约测试（`httpx.MockTransport`）覆盖企业微信发送接口与错误码映射。
- [ ] 用企业微信测试企业端到端发一条消息并收到回复（无测试企业时如实写明）。

## 外部条件

企业微信测试企业（自建应用：corpid、AgentId、Secret，可配置回调 URL）。
