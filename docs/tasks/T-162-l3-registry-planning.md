# T-162 L3 Agent 接入注册中心与 L2 交接

**版本**：V0.5（运行时架构 v2）　**依赖**：T-160、T-061、T-066　**PRD**：演进 PRD 23.1、6.7、7.6；`architecture-runtime-v2.md`

## 目标

L3（路径 B）是 ReAct 循环的 Agent，它的工具来自能力注册中心而不是各来源表各算一遍；它能拿到 L2 的候选作为提示；叶子智能体在多智能体场景下仍是它的委派工具。

## 范围

1. **工具来源改为注册中心**：`ToolRuntime` 从 `registry` 取当前智能体挂载范围内的注册项，生成模型可见的函数（名称、描述 = 委派描述 + 意图描述、参数 = `input_schema`）；原先按来源分别取规格的路径（`mcp_tool_specs` 等）退役，执行仍走 T-071 受控执行器，`ctx.allowed` 仍是“已挂载并勾选”的集合。每个挂载上的“勾选的工具 / 委派描述”（T-061）语义不变。
2. **L2 交接**：路径 B 带着 L2 的候选（名称、意图描述、得分）、已抽取的参数与转 B 的原因，作为系统提示里的一节“可能相关的能力”交给模型——只是提示，模型可以不用，也可以用别的工具。
3. **渐进披露**：该智能体可见的注册项超过 N（默认 30）时，不一次性把全部工具塞进上下文，而是只提供 L2 候选的前几个 + 一个元工具 `find_capability(query)`（在挂载范围内召回，返回名称与描述，使其在本轮可调用）。
4. **规划护栏**：最大迭代次数、整次运行的工具调用总数上限、同一工具同一参数重复调用的检测（第二次直接提示“已经调用过”，不执行）、总超时；超限后不带工具收束回答（沿用 T-061）。
5. **子 Agent 与知识库是注册项**：子 Agent 仍以 T-066 的委派工具（`agent:{id}`）提供，仅在多智能体开启时可见；它的注册项参与 L2 召回并作为提示交给 L3（`direct_enabled` 默认关）。知识库仍由主流程自动检索（沿用 T-033，不变）；注册项使它能出现在召回与“推荐能力”提示里，是否把知识库检索改成模型自己决定的工具留作后续。
6. **记录**：每次工具调用的 step 事件带注册 ID；`route` 记录里写明“L3 因何而来”。

## 验收标准

- [ ] 测试：工具列表等于“挂载并勾选的注册项”；停用 / 失效 / 挂载范围外的项不出现且伪造调用被拒绝；委派描述进入工具描述；写操作仍需确认（T-071）。
- [ ] 测试：L2 提示节出现在系统提示里且不含用户原文以外的敏感内容；渐进披露在超过阈值时只给元工具与候选，元工具只能召回挂载范围内的项；重复调用检测；调用总数上限。
- [ ] 回归：T-061 / T-066 既有用例（假模型 + 假提供者）全部通过。

## 不在范围

- L2 判断本身（T-161）；Skill 步骤执行（T-164）；执行策略（T-165）。

## 完成记录（2026-11-13，Claude Sonnet 5.5）

分支 `task/T-162-l3-registry-planning`，无迁移。

**后端**
- `ToolRuntime._resolve` 改为从注册中心取：`visible_entries`（已挂载并勾选、可用、子智能体仅在协作开启时）→ 工具规格（名称 = 执行器工具名，参数 = `input_schema`，写操作标记 = 注册项的 `writes`）；描述 = 挂载上的委派描述 + 意图描述 + 来源说明（≤ 1000 字）。按来源分别取规格的路径不再被 L3 使用；执行仍走 T-071 受控执行器，`ctx.allowed` 仍是“挂载并勾选”的集合。别名按“挂载顺序 → 名称”稳定排序（原来是来源列表顺序，旧测试里的别名序号因此变了）。
- **渐进披露**：可见工具超过 30 个时，只提供 L2 候选的前 5 个（按名称匹配）加元工具 `find_capability(query)`；元工具在挂载范围内召回（最多 8 个），返回别名与描述并使其从下一轮起可调用；未解锁的工具即使模型编出别名也被拒绝（`tool.not_found`）。每一轮重新取工具列表。
- **规划护栏**：整次运行的工具调用总数上限（`limits.max_tool_calls`，默认 20，1–100）、同一工具同参数重复调用不再执行（`tool.repeated`，提示“已经调用过”）、超限返回 `tool.limit_reached` 并要求直接回答；最大迭代次数与总超时沿用 T-061，超限后不带工具收束回答。
- 记录：工具 step 事件带 `entry_id`（注册项 ID）；“L3 因何而来”沿用 T-161 的 `route.handoff`。L2 候选作为“可能相关的能力”提示由 T-161 完成。

**验证**：ruff；`test_agent_runtime` 20 项（原 16 项适配：工具来自注册中心，测试里建真实 MCP 连接；新增 4 项：重复调用与总数上限、step 带注册 ID 与意图描述进入工具列表、超过阈值走 `find_capability`、未找到前不能调用隐藏工具）；全量后端见看板。

**遗留 / 说明**
1. 总数上限暂不能在智能体配置里调整（只有 DSL 默认值）；需要时再加到高级设置。
2. “L2 候选 → 渐进披露初始工具”由名称匹配实现，没有单独的集成测试。
3. 知识库仍由主流程自动检索，未改成模型自己决定的工具（规格已声明留作后续）。
