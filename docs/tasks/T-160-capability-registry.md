# T-160 统一能力注册中心

**版本**：V0.5（运行时架构 v2）　**依赖**：T-070、T-072、T-073、T-074、T-075　**PRD**：演进 PRD 23.2、7.1、7.6；`architecture-runtime-v2.md`

## 目标

L2 直达与 L3 规划共用一份“能力资产”：每项能力有稳定的注册 ID、输入 Schema、意图描述与示例、权限、超时与重试策略，并能按智能体的挂载范围被**召回**。不再让每个调度器各自从 MCP / API / Skill / Dify 的表里拼工具清单。

## 设计

- **注册项**（`capability_entries`，工具级）：`id`（稳定 UUID）、`tenant_id`、`kind`（`mcp_tool` / `api_tool` / `skill` / `dify_workflow` / `dify_chatflow` / **`agent`（子 Agent）/ `kb`（知识库，含 FAQ）**）、`source_type` + `source_id`（所属连接 / 插件 / Skill / 流程连接的 ID）、`identifier`（工具名 / 接口名 / Skill 名 / 应用标识）、`name`、`description`、`intent_description`（≤ 500 字，说明“用户想做什么时该用它”）、`intent_examples`（≤ 10 条示例问法）、`input_schema`、`writes`、`direct_output`（路径 A 的结果是否原样返回）、`status`（available / disabled / invalid，随来源而定）、`timeout_ms`、`retry`（`max_attempts`、`backoff_ms`、`retry_on`），`row_version`、审计字段。
- **不合并来源表**：注册项是**派生层**。来源（MCP 测试成功并勾选、API 插件解析并勾选、Skill 通过检查、Dify 连接保存 / 读取参数、**子 Agent 的发布 / 停用 / 改名、知识库的新建 / 改名**）变化时在同一事务里重算对应注册项；删除来源即让注册项失效。**子 Agent 与知识库不在“能力”目录里注册、也不在那里管理**：它们仍在各自的页面（智能体页、知识库页）里创建和编辑，注册项只是它们在统一能力里的视图；注册项的状态在读取时按来源的当前状态计算（沿用 T-070 的挂载解析器），不依赖缓存。来源表保持原样，注册 ID 不随重算改变（按 `source_id + identifier` 对账）。
- **范围**：一个智能体可见的注册项 = 它已挂载（并勾选）的来源展开的注册项（子 Agent 仅在开启多智能体协作时）。**`direct_enabled`**（路径 A 能否直达）默认：MCP / API / Skill / Dify = 是；子 Agent = 否（由 L3 委派，可在注册中心里打开）；知识库 = 否（只有 FAQ 高分直答由 T-161 单独处理）。
- **召回**（`registry.recall(db, tenant_id, assistant_id, query, k, history)`）：在可见注册项里按名称、说明、意图描述与示例召回前 k 个，返回注册项与得分。首版用 PostgreSQL 全文检索 + 关键词命中加权（与记忆检索同一套工具），接口里留出向量召回的替换点（不在本任务做向量）。
- **策略默认值**：超时与重试的解析顺序 = 注册项 → 租户默认 → 平台默认（30 秒、不重试）。本任务只存储与解析，**执行侧使用在 T-165**。

## 范围

1. 数据模型、迁移（可降级）、对账与失效逻辑；对已有 MCP / API / Skill / 流程连接做一次回填。
2. 接口（权限 `capabilities:view/edit`）：`GET /registry/entries?kind=&source_id=&q=`（租户内）、`PUT /registry/entries/{id}`（改意图描述与示例、`direct_output`、超时与重试，需 `row_version`）、`GET /assistants/{id}/registry/recall?q=&k=`（只看该智能体挂载范围内，供调试与 T-161 / T-162 复用）。
3. 前端：MCP 工具勾选列表、API 插件工具列表、Dify 连接页、Skill 详情里，每个工具 / 接口增加“意图描述与示例”“超时与重试”编辑；一个只读的“注册中心”视图（能力页新页签或设置里）列出所有注册项、来源与状态。
4. `architecture.md` 记录“注册项是派生层、挂载即授权范围”。

## 验收标准

- [ ] 测试：来源变化后注册项对账（新增 / 保留 ID / 失效 / 重新可用）；跨租户不可见；召回只返回该智能体挂载范围内的项；停用来源后召回不再返回；超时与重试默认值解析顺序。
- [ ] 测试：写操作标记（`writes`）与来源一致；`PUT` 校验 Schema 无关字段不可改（来源决定 `input_schema`）。
- [ ] 回填后既有挂载的 MCP / API / Skill / 流程连接都有注册项。

## 不在范围

- 向量召回与 embedding 基础设施。
- 执行侧的超时 / 重试 / 熔断（T-165）。
- Dify 应用参数的读取（T-163 提供 `input_schema`，本任务先用来源已有的映射）。

## 完成记录（2026-11-12，Claude Sonnet 5.5）

**迁移** `0052_capability_registry`（新表 `capability_entries`，可降级；PostgreSQL 升级 → `alembic check` 无差异 → 降级 → 升级已验证）。

**范围的澄清（产品 2026-11-12）**：子智能体与知识库（含 FAQ）也属于统一能力、有注册项，但它们**不在“能力”目录里注册或管理**，仍在各自的页面（智能体页、知识库页）里创建和编辑；注册项只是它们在统一能力里的视图，注册中心页签里的“所属”链接跳到各自的页面。

**后端**
- `capability_registry.py`：七种注册项——`mcp_tool`、`api_tool`、`skill`、`dify_workflow`、`dify_chatflow`、`agent`（子智能体）、`kb`（知识库）。**派生层**：一个 `after_flush` 监听器在**同一事务**里按来源重算（能力的名称 / 说明 / 工具清单变化，流程连接，智能体的名称 / 状态 / 发布 / 草稿配置变化，知识库的名称 / 说明 / 类型 / 删除），所以所有写入路径（接口、恢复、回滚、测试）都覆盖，没有人需要记得调用钩子。按 `(source_id, identifier)` 对账：来源拥有的事实（名称、说明、输入 Schema、是否写操作、元信息）被覆盖更新，注册中心独有的字段（意图描述、示例、`direct_enabled`、`direct_output`、超时、重试）**不会被重算碰到**；ID 稳定；来源或工具消失只标记 `removed_at`，回来时是同一个 ID 并保留设置。子智能体只在它能作为叶子被调用时（已发布、不是团队）才有注册项。
- **状态读取时按来源计算，不缓存**：沿用 T-070 的挂载解析器（`MOUNT_RESOLVERS`），MCP / API 工具再要求已勾选；来源不存在 = `invalid`，不可服务 = `disabled`。
- **范围**：`visible_entries` = 智能体已挂载的来源展开（子智能体仅在开启多智能体协作时），再按每个挂载上勾选的工具收窄；`recall` 只在这个范围里、只返回可用的项。召回是关键词匹配（名称、示例、意图描述、说明加权；中文按字符二元组，英文按词，忽略大小写），接口留作向量召回的替换点。
- `direct_enabled` 默认：MCP / API / Skill / Dify = 可直达；**子智能体、知识库 = 不可直达**（可在注册中心里打开）。
- 接口：`GET /registry/entries`（按类型 / 来源 / 关键词 / 状态筛选，带“所属”页面与 ID，列表不带 Schema）、`GET /registry/entries/{id}`（含 Schema 与解析后的策略）、`PUT /registry/entries/{id}`（只改注册中心独有的字段，需 `row_version`，来源拥有的字段即使提交也不会被修改；示例 ≤ 10 条、每条 ≤ 200 字，超时 1–300 秒，重试 1–5 次、间隔 ≤ 60 秒，`direct_output` 只在 `direct_enabled` 时有效；审计）、`POST /registry/resync`（重新同步，审计）、`GET /assistants/{id}/registry/recall`（该智能体范围内的召回，供 T-161 / T-162 复用）。
- 回填：**读取时懒回填**——一个租户没有任何注册项时（说明它早于注册中心），第一次列表 / 召回会把所有来源对账一遍；`resync` 是修复入口。（没有在迁移里回填，避免迁移依赖会演进的应用代码。）
- 策略（`resolve_policy`）：注册项自己的设置 > 平台默认（30 秒、不重试）；租户默认等 T-165。**只存储与解析，执行侧使用在 T-165。**

**前端**：能力页新增“注册中心”页签：全部注册项的卡片（类型、状态、是否写操作、所属、是否可直达、意图描述摘要）、按类型 / 状态 / 关键词筛选、“重新同步”；点击打开编辑（意图描述、示例每行一条、是否允许直达、是否直接返回结果、超时、重试次数 / 间隔 / 重试条件），无编辑权限时只读；子智能体与知识库的条目带“在智能体页 / 知识库页管理”的链接。中英文案。

**验证**：ruff；`test_capability_registry` 23 项（每种来源的派生与事实、直达默认值、来源拥有 / 注册中心拥有的字段分工与 ID 稳定、工具消失与回来、来源删除、子智能体只在可作叶子时出现、状态随来源且无缓存、知识库未索引 = 不可用、挂载与勾选范围、协作开关、召回排序与范围限定与 k、分词、列表筛选与所属、详情、编辑与审计与来源字段不可改、无效编辑被拒、权限 / CSRF / 跨租户、读取时回填、重新同步修复、租户隔离、策略解析）；前端 tsc / lint / i18n / style / build；全量后端见看板。

**与规格的差异 / 遗留**
1. 规格里“每项带**权限**”：没有单独存一个权限字段——谁能用一项能力由“挂载（授权范围）+ 勾选的工具”决定，谁能管理由来源的 RBAC 决定；再加一个未被检查的字段只会误导。如需按角色限制终端用户可用的能力，另议。
2. 规格里“MCP 工具勾选列表、API 插件工具列表、Dify 连接页、Skill 详情里编辑意图描述与超时重试”：**只在注册中心页签里编辑**（所有类型统一一处，子智能体与知识库也在这里补充），没有改动各来源的详情页。
3. 没有迁移时回填（见上，读取时懒回填）。
4. 召回只有关键词匹配；没有向量；中文没有分词（二元组），短问题对长描述的匹配会偏弱——意图示例写得越像用户的问法，效果越好。
5. 知识库中的 FAQ 没有单独的注册项（知识库一项，`meta.kb_type` 标明类型）；T-161 的“FAQ 直答”在知识库项上做。
