# T-058 OC · 路由

**版本**：V0.2　**依赖**：T-057、T-061、T-070　**PRD**：3.6.7（OC-060–064）、AST-065、5.5 第 7 步、RUL-011、RUL-014

## 范围

1. 路由配置（OC-060、OC-062、OC-063）：路由模型、置信度阈值、自定义提示词、优先规则开关与列表、意图澄清（轮次、中英文话术）、兜底（固定回复 / 默认能力）。路由目标 = 已挂载且可用的 Agent（含协作组）、Chatflow、Workflow（T-070 能力目录）。
2. 规则编辑页（OC-061）：关键词/正则（忽略大小写、中英文逗号）、优先级默认值、目标卡片、即时测试、保存条件；目标以 ID 保存，按名称唯一匹配时自动修复（OC-060 目标修复）。
3. 运行时（OC-064）：中断等待的 Chatflow 优先 → 优先规则（优先级、同级按创建时间）→ 语义路由（LiteLLM 结构化输出：目标 ID + 置信度 + 理由）→ 意图澄清（多轮合并上下文）→ 兜底；无可路由目标时助理自身应答。
4. 与 T-057 的配合：开启“仅低置信度时改写”时，先用原文语义路由，置信度达标则不改写；不足再改写后重路由。复杂问题拆解的子问题分别路由并合并回答（合并由助理模型完成）。
5. 失效引用：目标被停用/删除/卸载后规则显示“目标失效 / 待重选”，总览计数；默认能力失效时用固定回复（OC-063）；含失效路由目标的助理发布时检查列为“高影响”（RUL-011，接入 T-021 配置检查）。卸载被规则引用的能力时确认（AST-065）。
6. 路由结果（命中规则 / 置信度 / 澄清轮次 / 兜底）写入 trace 与 run 事件；测试控制台显示「路由 → {目标} · {耗时}」（AST-054）。

## 验收标准

- [ ] 单元测试（假模型）：规则优先级、同级排序、停用规则不执行、阈值边界、澄清轮次上限后兜底、中断 Chatflow 优先。
- [ ] 测试：路由目标只能是本租户本助理已挂载的可用对象（伪造目标 ID 被忽略）。
