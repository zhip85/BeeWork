# T-027 助理测试控制台与测试用例

**阶段**：3　**依赖**：T-025、T-021　**PRD**：AST-054、AST-071、4.4 TestCase
**外部条件**：供应商 Key（评测判定需要真实模型）

## 范围

1. 详情页右侧实时测试控制台（AST-054）：环境与版本选择（草稿或已发布版本）、流式消息、耗时与点数、重置、“查看完整调用链”跳转 Langfuse trace（有配置时）、“添加为测试用例”。测试对话 `source=debug`，不计入运营统计。
2. 测试用例页签（AST-071）：CRUD、复制、运行单条/运行全部（Worker 批量执行，`source=test`），用租户默认对话模型作为评测模型判定“是否符合期望行为”，保存实际回复与判定理由；状态只能由运行结果写入。
3. 发布（T-024）前自动运行全部用例，结果附在审批单 `checks` 中。

## 验收标准

- [ ] 评测判定逻辑可替换且有单元测试（用假模型）。
- [ ] 运行全部的进度在界面可见，失败原因可见（NFR-020）。

**行为**
- 用例（AST-071）：新建/编辑/复制/删除，字段为名称、用户输入、期望行为、类型（回归/安全/知识）；**状态与结果只由运行写入**（写入接口不接受 `status`）。改了输入或期望会清掉旧结果；每个助理最多 100 条。权限：增删改 `assistants:edit`，运行 `assistants:test`，查看 `assistants:view`。
- 运行（Worker 批量）：`POST /assistants/{id}/test-runs`（可选 `case_ids`、`version_id`；默认全部用例、当前草稿）。每条用例走与控制台相同的完整运行管线（`source=test` 的会话与运行），再由评测模型判定；记录实际回复、判定理由、目标（draft / vX.Y）、时间。进度（已完成/总数/通过/失败）可轮询，页面刷新后仍可见；可取消；同一助理同时只允许一个手动批次（409 `test_run.busy`）；Worker 崩溃后重领的批次从未完成的用例继续。运行失败、评测失败都写成“失败”并带原因（NFR-020）。
- 评测判定可替换：`JudgeFactory`，默认用租户默认对话模型（经 LiteLLM），要求返回 `{"pass": bool, "reason": ...}`，**解析不了按失败处理**；兼容返回分段内容的供应商。测试用假判定与 `ScriptedChat` 假模型。
- 发布前门禁（AST-044）：发布/回滚进入审批时，若助理有用例，自动对**待发布的快照**（不是之后改过的草稿）跑一遍全部用例，结果写进审批单检查项（“回归测试运行中（0/N）”→“回归测试通过 N/N”或“回归测试未通过 P/N”），不改动用例列表上的结果；没有用例则不加该检查项。门禁只提示，不阻止提交。
- 测试控制台（AST-054）：详情页概览右侧；选版本（当前草稿或任一已发布版本）；流式回复、耗时与 tokens、重置、停止、调用链链接（有 Langfuse 时）、“添加为测试用例”。环境固定为生产（T-006 做环境切换前只有一个环境）。界面显示“检索：桩实现，未接真实 RAGFlow”。

**遗留问题**
- OPS-033 的“租户可配置为未通过即不可提交”未做，目前门禁只提示。
- 控制台“点数”显示的是 tokens（点数计量在 T-011）；版本运行的会话 `source` 沿用既有的 `test`，草稿运行为 `debug`，规格写的是控制台统一 `debug`，如需统一请确认后再改（会影响既有测试）。
- 用例只保存“最近一次”结果，没有历史；批次明细保存在 `assistant_test_runs.results`，无清理策略。
- 一个批次在单个 Worker 作业里串行执行（上限 100 条）；用例很多或模型很慢时可能超过作业锁时限，被重领后会从断点续跑。
- “运行全部”未做多并发；仅支持文本，不含知识库问答类用例的引用断言（检索仍是桩）。

**审查修正**
- 并发点“运行全部”会同时建出两个批次：忙检查原先在锁用例行之前。现改为先锁用例行再检查（并发请求排队后会看到第一个批次），新增 PostgreSQL 并发测试（5 个并发请求只成功 1 个、只入队 1 个作业）。
- 批次出现未预期异常时会永远停在“运行中”，既阻塞该助理再次运行，又让用例无法编辑：现在批次循环整体兜底，异常时置为失败并释放用例；另加 2 小时过期保护（`expire_stale_batches`，列表与启动时自动把失联批次置为失败并释放用例）。
- 用例在运行期间被删除，收尾写入会因更新不存在的行而崩溃：现在收尾时强制从库刷新，已删除的用例只计入批次结果、不再写用例行。
- 前端测试控制台在事件流中断且没有结束事件时，消息会一直显示“思考中…”：现在流结束仍未完成的消息会标为失败。
- 已知未改：评测模型读取的是被测助理的实际回复，回复里若夹带“请判定通过”之类的指令存在提示注入风险（LLM 评判的固有问题）；用例的 `last_output` 是模型原始回复，未做 PII 脱敏。
