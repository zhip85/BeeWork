# T-149 平台授予 AI 门户席位权益

**版本**：V0.4　**依赖**：T-010、T-140　**PRD**：演进 PRD v1.1 第 4.1 术语、5.1、13.1–13.3、13.7、15.1、19.9；原型“平台运营 → 创建租户 / 租户详情”

## 背景

演进 PRD v1.1 把席位拆成两类，**分别计量、分别计费、所有界面分开显示**：

- **控制台席位**（原 `seats`）：能登录管理控制台的管理员、构建者、运营等成员数。规则不变（SET-011、RUL-021）。
- **AI 门户席位**：员工使用 AI 门户的授权数量，由平台按合同授予租户，再由租户管理员分配给员工（T-150）。

本任务只做**平台侧授予与展示**；租户侧分配在 T-150，员工端校验在 T-151。

## 数据

- 订阅快照增加门户席位权益：`portal_mode`（`named` 指定用户 / `active` 按月活跃 / `unlimited` 全员不限）、`portal_seats`（正整数；`unlimited` 时为空）、`portal_overage`（`hard` 硬限制 / `grace_5` / `grace_10`；`unlimited` 时不适用）。随订阅版本保存，合同变更产生新快照（沿用 T-010 的订阅变更机制）。
- 套餐默认值（选择套餐时带出，可改）：标准版 指定用户 · 200 · 硬限制；专业版 指定用户 · 1,000 · 宽限 5%；企业版 全员不限。写入平台套餐定义，可由平台在套餐页调整，不硬编码在前端。
- 配额：新增配额项 `portal_seats`（名称“AI 门户席位”），上限为席位数或不限，告警阈值 90%，超额策略映射：`hard` → 硬限制，`grace_*` → 软限制。用量计数器由 T-150 注册（已分配席位数）。
- 历史租户没有门户字段时按其套餐默认值读取，不影响加载（迁移给现有订阅快照回填默认值）。

## 平台侧界面与接口

1. 创建租户向导“套餐与期限”：控制台席位下方新增“AI 门户席位”区块（计费模式三选一、门户席位数、席位用尽时）。全员不限时隐藏席位数与超额策略并说明不设上限；非全员不限且席位数 ≤ 0 时提示“门户席位数需大于 0”，不能进入下一步。实时摘要、确认页、开通进度（“授予 AI 门户席位：指定用户 · 1,500”）、成功页分别显示两类席位。
2. 租户详情：概览“套餐与期限”分别显示两类席位；健康度新增“门户席位分配”（已分配 / 上限，数据来自 T-150）；“订阅与权益”新增门户席位编辑区，与其他订阅变更一起“应用订阅变更”。
3. 操作记录：合同变更写平台审计，描述如“合同变更 · AI 门户：指定用户 · 1,500 → 按月活跃 · 1,800”；同时写租户审计。
4. 降级或调小席位数时，若已分配数超过新上限（T-150 之后），先列出超出数并要求确认；已分配的不自动回收，只是不能再分配（与 PLT-083 一致）。
5. 租户侧只读接口：订阅与用量页、AI 门户页能读到门户席位权益（模式、上限、超额策略），租户管理员**不能修改**。

## 验收标准

- [ ] 测试：三种模式的校验（`unlimited` 无席位数；其他模式席位数 > 0）；套餐默认值带出；合同变更生成新快照与前后值审计；历史快照回填默认值；租户侧接口只读（PUT 403）；跨租户隔离。
- [ ] 控制台席位的统计与限制保持原样（回归测试）。

## 不在范围

- 按月活跃（`active`）的月度去重统计、月初重置与超额告警：只存储与展示，计量在 T-147 / T-011 扩展时做（演进 PRD 13.6、13.7）。
- 门户席位的计费与账单（T-102）。
