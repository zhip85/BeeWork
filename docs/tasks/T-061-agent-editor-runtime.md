# T-061 Agent 编辑器与 Agent 运行时

**版本**：V0.2　**依赖**：T-060、T-033、T-071　**PRD**：3.3.4（AGT-030–031）、AGT-027、AST-021 驱动方式、RUL-014、5.5 第 8 步

## 编辑器（AGT-030–031）

- 指令（≤ 8000 字）与用途描述；模型下拉为当前环境已启用的对话模型，已停用的当前模型仍显示并标红。
- 资源区：技能、工具（MCP 工具与 API 插件的**具体工具**）、知识、连接的智能体（除自身外的 Agent、协作组、Chatflow、Workflow）、渠道（仅引用展示）；“连接{区域}”弹窗只列可用资源（T-070 能力目录）；失效标签红色。
- 记忆开关（智能体级，默认关）：开启后同一终端用户多次调用间保留记忆，存储复用 T-056 的 UserMemory（按 agent 隔离）。

## 运行时

- 编译为 LangGraph 工具调用循环：模型经 LiteLLM（`resolve_model_alias`）；工具 = 挂载知识库的检索工具（T-033）+ 能力工具（经 T-071 执行器）+ 连接的智能体（作为子调用工具，传入用途描述）。
- 约束：最大迭代次数（默认 8）、总超时（默认 60 秒）、嵌套调用深度 ≤ 5（RUL-014，深度随调用上下文传递，超过时返回错误给上层模型）。
- 智能体的输入输出仍经过引用它的助理的 OC 管线（AGT-027）：Agent 只在 `execute` 阶段运行，不自带 PII 阶段。
- 助理“驱动方式”（AST-021）：助理草稿可指定一个可用 Agent 或协作组为驱动方，`execute` 阶段由该 Agent 应答；未指定时助理自身提示词应答。T-020 向导的驱动方式下拉在本任务接入。
- 运行使用 `available_config`；调试（编辑器内试用）使用草稿，`source=debug`。
- 每次工具调用、子智能体调用都是一个 Langfuse span。

## 验收标准

- [ ] 单元测试（假模型）：工具调用循环、迭代上限、超时、深度上限、工具不在挂载列表时拒绝执行。
- [ ] 测试：助理以 Agent 为驱动方时，线上运行使用 Agent 的可用配置而不是草稿。
- [ ] 真实模型跑通一次“Agent 调用知识检索后回答”（有 Key 时），记录在 development-status。
