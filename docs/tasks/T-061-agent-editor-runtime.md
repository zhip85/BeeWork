# T-061 智能体编辑器补全与工具调用运行时

**版本**：V0.2　**依赖**：T-070、T-071、T-033　**PRD**：演进 PRD 6.2（Agent）、6.4、6.6、7.6、9.4 第 7 步；原 PRD AST-021、RUL-014
**外部条件**：供应商模型 Key（真实验收需要）

> **2026-11-10 需求变更**：演进 PRD 取消独立的“助理”概念，智能体 = 现有助理（`assistants` 表、详情页、OC、渠道、版本）。原规格中“`agents` 表里的 Agent 编辑器”与“助理驱动方式（driven_by）”作废：不再有“助理由某个 Agent 驱动”，智能体自己就是执行者。多智能体协作见 T-066。

## 编辑器补全（在现有智能体详情页“基础”“能力”中实现）

1. 身份与指令（演进 PRD 6.4）：在现有名称、简介、提示词、默认语言之外增加**角色**（一句话）与**回答风格**（简洁 / 均衡 / 详细，默认均衡）。
2. 模型：主模型（已有）+ **备选模型**（主模型调用失败或被停用时使用，只能选租户已启用的对话模型）+ 温度（0–2，默认 0.7）+ 最大输出 token（1–模型上限，默认按模型）。配置存 `draft_config`（新增字段带默认值，旧数据可读，不需要迁移），随版本快照冻结。
3. 能力：挂载选择器支持 T-070 注册的全部类型（知识库、Skill、MCP、API 插件、Chatflow 连接、Workflow 连接、叶子智能体（T-066））；每项挂载可配**允许的工具 / 操作**（最小权限，演进 PRD 7.6、15.3）与**委派描述**（何时调用）。失效挂载红色显示并计入配置检查。
4. 移除“驱动方式”字段的界面与 `driven_by` 的使用（字段保留可读，不再写入；在 development-status 记录）。

## 工具调用运行时

- 现有 `execute` 阶段从“单次 LLM 调用 + 检索”升级为 LangGraph **工具调用循环**：可用工具 = 挂载知识库的检索工具（T-033）+ 挂载能力的具体工具（经 T-071 执行器）+ 挂载的流程连接（T-075）+ 叶子智能体（T-066，作为子调用）。工具描述取挂载项的委派描述。
- 约束：最大迭代次数（默认 8）、总超时（默认 60 秒）、调用深度上限（演进 PRD 6.7 只允许一层协作，深度实际 ≤ 2；超限返回错误给模型）。
- 备选模型：主模型返回错误或不可用时切换一次，trace 记录切换原因。
- 线上运行用冻结的版本快照；测试控制台用草稿（`source=debug`）。
- 每次工具调用一个 Langfuse span；工具结果仍经 OC 输出网关。

## 验收标准

- [ ] 单元测试（假模型）：工具调用循环、迭代上限、超时、工具不在挂载列表或未勾选时拒绝执行、备选模型切换。
- [ ] 测试：新增配置字段对旧草稿与旧版本快照兼容（读取时补默认值）。
- [ ] 真实模型跑通一次“智能体调用知识检索后回答”（有 Key 时），记录在 development-status。

## 完成记录（2026-11-12，Claude Sonnet 5.5）

**无迁移**：新增配置字段都在 JSON 里且带默认值，旧草稿与旧版本快照读取时补默认值（有测试）。

**配置（`draft_config` / `AssistantDSLv1`）**：角色（≤ 200 字）、回答风格（简洁 / 均衡 / 详细，默认均衡）、备选模型 `fallback_model_id`、温度 0–2（默认 0.7，真正传给模型）、最大输出 token 16–8192（默认运行时 1024）、`limits.max_iterations`（默认 8）、`tools.mounts`（MCP / Skill 挂载及其勾选的工具与委派描述）。角色与风格进入系统提示词；默认值（无角色、均衡）下系统提示词与之前**完全一致**。保存时校验：备选模型必须是已启用的对话模型且不能等于主模型（422 `assistant.fallback_model_unavailable`）；挂载设置里勾选的 MCP 工具必须是该连接管理员已勾选的工具（最小权限，422 `assistant.mount_settings_invalid`）；配置检查对未启用的备选模型给出“高”级问题。`driven_by` 不再写入也不再显示（字段保留可读）。

**工具调用运行时**：`execute` 阶段在检索之后进入 LangGraph 阶段内的工具调用循环（`runtime/compiler.py`）：模型可用的工具 = 该智能体挂载并勾选的 MCP 工具 + 挂载的 Skill 加载工具（`runtime/tool_runtime.py`，工具描述 = 委派描述 + 工具描述；每次运行以租户当前的行为准，已删除 / 停用的能力不再提供）；每次调用都经 T-071 的受控执行器（存在性、是否在允许集合、深度、参数 JSON Schema、写操作确认、凭据清洗、结果经 `pii_output` 同一套规则后才给模型、只记元数据）；每次调用一个 Langfuse span（`tool.<name>`）和一条 `step` 事件（工具、状态、耗时、错误码）；模型编造的或未勾选的工具被拒绝且不执行；参数不合法、工具失败、需要确认的写操作都以文字回传给模型。约束：最大迭代次数 8，达到后再做一次**不带工具**的调用并提示“已达到工具调用次数上限”以便给出最终回答；总超时沿用 `limits.timeout_seconds`（工具循环内每个 chunk 和每次工具调用前都检查，超时 / 取消立即停止）；调用深度 1（≤ 5 的上限由执行器保证）。token 用量跨轮累计。线上用冻结快照、控制台用草稿，沿用原有逻辑。
**备选模型**：主模型在**尚未输出任何内容**时报错，切换到备选模型重试一次（只切一次）；已输出内容后不切换（避免重复内容）；切换原因记在 `step` 事件 `model_fallback` 与 span `model.fallback`；主模型被停用但备选可用时，准入检查（开放 API / 挂件 / 门户 / 控制台运行）也放行，由运行时切换。

**验证**：`ruff` 通过；`test_agent_runtime`（16 个，用脚本化的会调工具的假模型 + 假 MCP 提供者，走真实执行器与真实 Run / 事件 / ToolInvocation 记录）：模型调用工具并基于结果回答（两轮用量累计）、只提供挂载且勾选的工具、委派描述进入工具描述、未勾选 / 编造的工具拒绝且不执行、参数不合法 / 工具失败 / 写操作需确认都回传模型且只有合法只读调用被执行、迭代上限、总超时、工具结果经输出规则、备选模型切换一次与备选也失败不再重试与无备选时原行为、旧草稿和旧快照兼容、草稿到 DSL、角色与风格入提示词且默认不变、温度传给模型、保存校验；加上 `test_runtime`、`test_assistants`、`test_open_api`、`test_mcp`、`test_skills`、`test_tool_executor`、`test_conversations`、`test_capability_catalog` 等共 218 个测试通过。前端 `tsc` / `lint` / `i18n:check` / `style:check` / `build` 通过；浏览器看了基础页（角色、回答风格、备选模型、温度、最大输出 token 已出现，驱动方式已移除）；开发环境用门户走了一次完整的运行（检索 + mock 模型）确认老路径未被破坏。

**真实模型 / 真实工具：没有。** 开发库的聊天模型是 `mock_response`（不会发起工具调用），开发环境也没有可连的 MCP 服务器，所以“模型调用真实 MCP 工具”只在假模型 + 假提供者下验证；验收要求的“真实模型跑通一次智能体调用知识检索后回答”需要供应商 Key，未做。

**与规格的差异 / 遗留**
1. **知识库检索仍是自动的前置步骤**（沿用原来的检索后注入上下文），没有改成“模型自己决定是否调用的检索工具”——避免在没有真实模型验证的情况下改变已验收的检索行为；需要时作为后续任务。
2. **只接入 MCP 与 Skill 两类工具**；API 插件（T-073）、Chatflow / Workflow 连接（T-075）、叶子智能体（T-066）还没有提供者，等它们落地后只需注册提供者并在 `ToolMount.kind` 加类型。
3. **写操作的用户确认没有交互流程**：执行器会抛“需要确认”，当前运行时把它作为一条失败文字回传给模型（不执行）；真正的“中断 → 询问用户 → 恢复”需要运行事件与渠道协议配合，留待后续。
4. 备选模型的“主模型被停用”场景：准入已放行，运行时由网关拒绝后切换；未单独写端到端测试（备选切换本身有测试）。
5. 最大输出 token 上限用 8192（不是各模型自己的上限）；“温度 / token”没有按模型能力裁剪。
6. 未跑全量后端测试（主机负载高）；合并前补跑。
