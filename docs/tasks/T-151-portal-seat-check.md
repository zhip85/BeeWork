# T-151 员工端门户席位校验与开通申请

**版本**：V0.4　**依赖**：T-150、T-142　**PRD**：演进 PRD v1.1 第 5.3、5.4、13.5、13.7、19.9

## 范围

1. **两个独立判定**（演进 PRD 5.4）：认证（你是谁）成功后，再判定席位（你能否使用门户）。门户可用条件改为：`持有门户席位（或租户为全员不限）` 且 `应用已上架` 且 `在可见范围内` 且 `来源仍有效`。
2. 服务端校验：提供依赖 `require_portal_seat`，**所有** `/api/v1/portal/me/*` 中使用门户的接口（对话、发消息、项目、应用库、个人中心等）都要挂上；`portal_service.visible_apps` 对无席位成员返回空。校验在会话建立和每次应用调用时生效，前端状态只用于展示。
3. 登录后的席位状态接口 `GET /portal/me/seat`：`assigned` / `requested` / `unassigned`，以及是否可申请。
4. 首次登录自动分配：租户开启且仍有可分配席位时，未持有席位的员工首次进入门户即分配（来源 `auto`，受 T-150 容量规则约束，并发安全），响应提示“已自动为你分配门户席位”。
5. 无席位页（中英文）：“你暂未开通 {门户名称}”，说明身份已验证但尚未分配席位，申请原因输入框 + “申请开通”、“使用其他账号”；待审批页：“申请已提交”，等待管理员审批。管理员通过后再次进入即可使用，驳回后回到可申请。
6. 申请 `POST /portal/me/seat/request`（原因 ≤ 200 字，重复申请幂等），通知租户管理员（有 `portal:publish` 的成员）。
7. 门户会话建立时更新成员的最近登录时间（T-150 闲置回收使用）。

## 验收标准

- [ ] 测试：无席位访问任一门户接口 403 `portal.seat_required`；全员不限时不要求席位；自动分配在满额时不分配并显示无席位页；申请 / 审批通过 / 驳回的状态流转；并发首次登录不超额（PostgreSQL）。
- [ ] 浏览器验证无席位页、申请、待审批、通过后进入门户的完整流程（中英文各看一次）。
