# T-120 KMS 信封加密与密钥轮换

**版本**：V1.0（生产门禁）　**依赖**：无（越早越好）　**PRD**：NFR-008、PLT-081（企业版加密密钥）、technical-plan“首发部署区域与 KMS”
**外部条件**：生产 KMS 选型（随部署区域决定）；未决定前只交付接口、本地实现与 Vault Transit 实现

## 范围

1. `KeyProvider` 接口：`encrypt_dek`、`decrypt_dek`、`rotate`；实现：`local`（开发，主密钥来自环境变量）、`vault_transit`（开源，可私有化）、云 KMS 适配器（选型确定后实现）。
2. 信封加密：每租户一把数据密钥（DEK），密文字段格式带 `key_version`；替换 `model_secrets` 当前的 Fernet 单密钥方案，覆盖所有 secret 字段（模型 Key、BYOK、渠道凭证、MCP/OAuth 令牌、Webhook 签名密钥、SSO 客户端密钥、LDAP 密码）。
3. 迁移：后台任务把旧密文重新加密为新格式，可中断续跑；读取兼容新旧两种格式直到迁移完成。
4. 轮换：主密钥轮换不需要重加密数据（只重加密 DEK）；DEK 轮换任务按租户执行。
5. 企业版客户自有密钥：租户 DEK 由客户提供的 KMS 密钥包裹（配置项预留 + Vault 实现验证）。
6. 运维文档：密钥丢失、轮换、应急吊销流程。

## 验收标准

- [ ] 测试：新旧格式兼容读取；迁移可续跑且幂等；错误密钥解密失败不泄露明文；日志中无密钥材料。
