**版本**：V0.4　**依赖**：T-143、T-011　**PRD**：演进 PRD 10.5；原型“AI 门户 → 使用分析”

## 范围

- 指标（按 `source=portal` 的 runs、门户会话与反馈统计，租户隔离）：活跃员工、应用调用量、成功率、员工评分（赞踩折算，算法在任务内写明）、热门应用排行、趋势（按日）；时间范围 7 / 30 / 90 天，环比。
- 管理端 AI 门户页的“已上架应用 / 月活跃员工 / 本月使用次数”卡片接真实值。
- 只读，`portal:view`。

## 验收标准

- [ ] 测试：统计口径（只算 portal 来源、只算本租户、时间窗边界）；没有数据时返回 0 而不是 500。

- 增加门户席位指标：已分配 / 合同数、待审批、闲置；“按月活跃”模式下按计费周期统计去重活跃员工并在超额时告警（演进 PRD 13.7）——本任务提供统计口径，计费在 T-102。

## 完成记录（2026-11-12，Claude Sonnet 5.5）

**无迁移**。统计口径写在 `portal_analytics.py` 顶部并显示在页面底部：
- 只统计 `source=portal` 的运行；**员工** = 运行所属对话的门户终端用户；活跃员工 = 窗口内发起过调用的不同员工；调用量 = 运行数。
- **成功率** = 成功 /（成功 + 失败），不含进行中（queued / running）与员工取消的运行；没有可统计的运行时为空（不显示 0 或 100%）。
- **员工评分（赞踩折算）** = 赞 /（赞 + 踩），统计窗口内员工对门户对话回答的评价；没有评价时为空。为此新增员工端评分接口 `PUT /portal/me/conversations/{cid}/messages/{mid}/feedback`（赞 / 踩 / 清除；只能评自己对话里的回答，别人的、用户消息、不存在的都是 404），员工端回答下方有赞 / 踩按钮，复用 `messages.feedback`。
- **时间窗** `[现在 − N 天, 现在)`（N = 7 / 30 / 90，起点含、终点不含）；**环比**与紧邻的前一个等长窗口比较，变化 = 当前 / 之前 − 1，之前为 0 或没有值时不给变化（显示“无对比数据”，不是无穷大）；趋势按 UTC 自然日，缺失的日期补 0；**本月**为 UTC 自然月（本月活跃员工、本月调用量）。
- 热门应用：按调用量排序，前 10，含活跃员工与成功率（应用已删除时名称显示 “—”）。

**接口**：`GET /portal/analytics?days=7|30|90`（`portal:view`，只读，其他取值 422）返回四个指标（值 / 前值 / 变化）、赞踩数、热门应用、每日趋势、门户席位指标（已分配 / 合同数、待审批、闲置、本月活跃员工）；“按月活跃”模式下本月活跃员工超过合同席位数时 `over_active_limit=true` 并在页面提示（计费在 T-102）。`GET /portal/summary`（管理端“月活跃员工 / 本月使用次数”卡片）现在返回真实值，不再是空。

**前端**：AI 门户新增可用的“使用分析”页签：时间范围切换、四张指标卡（含环比箭头）、每日调用趋势柱状图、热门应用表、席位指标、口径说明；管理端概览卡片接真实值。中英文齐全。

**验证**：`ruff` 通过；`test_portal_analytics`（9 个）通过，并与 `test_portal_chat`、`test_portal_seat_check`、`test_portal_seats`、`test_portal_apps`、`test_portal_settings` 回归。测试覆盖：没有数据时全 0 / 空而不是 500、只算门户来源（api / debug 不算）与本租户（别的租户的门户运行不算）、时间窗边界（终点不含、起点含、前一窗口起点含、更早丢弃）、成功率排除进行中与已取消、去重活跃员工、热门应用与趋势、环比、评分与清除评分、他人 / 用户消息 / 不存在的消息评分 404、按月活跃超额提示、参数 422、员工 403、跨租户 403、未登录 401、概览卡片的真实月度值。前端 `tsc` / `lint` / `i18n:check` / `style:check` / `build` 通过；浏览器（开发库租户管理员）检查了使用分析页与概览卡片（开发库的数据很少，且回答来自 mock 模型）。

**遗留 / 说明**
1. 统计在 Python 中汇总（窗口内的运行逐行读取），租户量大后（90 天数十万次运行）再改 SQL 聚合 / 汇总表。
2. 趋势的第一天是不完整的一天（窗口按 N×24 小时而不是整日）。
3. “按月活跃”的计费周期这里按自然月近似，真实计费周期在 T-102 / T-011 扩展时对齐。
4. 员工评分按对话回答统计，没有按应用拆分的评分；没有导出。
5. 未跑全量后端测试（主机负载高）；合并前补跑。
