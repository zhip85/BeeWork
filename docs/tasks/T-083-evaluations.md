# T-083 评测与发布门禁

**版本**：V0.3　**依赖**：T-027、T-082、T-024　**PRD**：3.8.4（OPS-030–034）、5.1 评测状态机、PLT-081（评测与发布门禁权益）

## 设计（已定）

- BeeWork 保存评测任务、数据集与逐用例结果（业务事实，供详情与对比）；执行由 Worker 调用运行时（`source=eval`）对指定助理版本或草稿逐条运行，判定经 LiteLLM 调用评判模型。
- 同时把数据集与运行结果写入 Langfuse（SDK ≥ 3 的 datasets / dataset run 与 score 接口），使每个用例的 trace 能在 Langfuse 中对照；Langfuse 未配置时跳过，不影响评测。

## 范围

1. 新建评测（OPS-031）：名称、助理与版本（草稿或已发布版本）、数据集（助理测试用例 / 上传 CSV `input,expected,type` / 按标签筛选的标注会话）、指标多选（回答准确率、有据性、安全性、延迟）、通过阈值（默认 85%）、评判模型（当前环境已启用的对话模型）。
2. 状态（5.1）：排队中 → 运行中 → 通过（得分 ≥ 阈值）/ 失败；执行异常也记为失败并记录原因；进度可见（NFR-020）。
3. 详情（OPS-032）：总分与各指标、与上次评测对比、用例明细（输入、期望、实际、各指标得分、失败原因、调用链接）、导出 CSV。
4. 发布门禁（OPS-033）：助理“发布更新”时自动运行回归用例（T-027 已有）并附评测结果到审批单 checks；租户可配置“未通过不可提交”（合规与审批页增加一项）。
5. 计费（OPS-034）：评测调用在用量中单列为“评测”（T-011 `source=eval`）。
6. 评测完成发站内通知给发起人（5.8）。权益：评测（专业版及以上）。

## 验收标准

- [ ] 测试（假模型）：得分计算、阈值判定、异常记失败、门禁开启时未通过不能提交审批。
- [ ] 有 Langfuse 时，一次评测在 Langfuse 中能看到 dataset run 与 score（记录在 development-status）。
