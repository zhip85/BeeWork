# T-110 案例数据工作室

**版本**：V1.0　**依赖**：T-001（各业务集合在其模块完成后接入）　**PRD**：3.11（CSD-001–003）、GLB-068、4.13、8.3#14、8.3#21

## 目标

把原型中的“案例数据”能力做成服务端功能：按集合查看、导入、导出、生成示例、恢复默认、填充示例数据，全部按租户/平台边界授权并写审计。

## 设计

- 集合注册表：`@case_collection("assistants", scope="tenant", model=Assistant, ...)`，每个集合声明作用域（租户 / 平台）、序列化与反序列化、导入校验（复用该领域的 Pydantic schema 与业务校验，**不允许绕过业务规则直接写表**）、权限点、示例数据生成器与默认数据。
- 有正式业务模块的集合由各模块注册；4.13 中没有业务页面的预留集合（智能体任务、智能体中心、外部流程、数据源、意图澄清规则、智能体委派、推广、模板市场、安全与合规）存放在通用表 `case_data_records`（作用域、集合 ID、JSON 记录、审计字段），只在本页面管理（8.3#14）。
- 已被正式页面替代的集合（审批流、环境/凭证/预算、品牌/语言）不再单独提供，在列表中标注“已由 {页面} 替代”。

## 范围

1. 页面（CSD-001）：统计、按模块列出集合与记录数、所选集合的通用列表（2.4）、导入（粘贴 `{"集合ID": [记录]}` 合并导入，先预览校验结果再确认）、导出 JSON。租户侧与平台侧各一个入口（租户管理员 / 平台管理员）。
2. 列表内操作（CSD-003、GLB-068）：生成示例、恢复默认、填充示例数据——作用于服务端，展示结果，写审计（操作者、集合、条数）。
3. 导入导出与 T-128 的环境迁移包使用同一序列化，避免两套格式。

## 不在范围（阻塞项）

- **“全部重置”**：8.3#21 未确定权限、作用范围与恢复策略。在决策前不实现，按钮显示为不可用并提示“待确认”。决策需包括：谁能执行、是否只限当前租户、执行前是否自动备份、能否撤销。

## 验收标准

- [ ] 测试：导入不能写入其他租户；导入非法记录逐条报错且不部分写入；租户账号不能操作平台集合。
- [ ] 每个已完成业务模块至少注册一个集合并通过导入—导出往返测试。
