# T-167 Office 插件（Word / Excel 任务窗格）

**版本**：V0.5（运行时架构 v2）　**依赖**：T-143、T-146（员工门户对话与登录）　**PRD**：演进 PRD 23.5；`architecture-runtime-v2.md`

## 目标

员工在 Word / Excel 里打开任务窗格，直接和智能体对话，并能把选中的内容作为输入、把回答插回文档。

## 范围

1. **任务窗格页面**（`/office/taskpane`，BeeWork 前端的独立入口，懒加载）：沿用员工门户的会话与对话接口（T-143），登录用门户身份（T-142 / T-146，Office 加载项的弹出窗口完成登录，令牌存在窗格里）；应用选择限于该员工可用的门户应用。
2. **Office.js 能力**（Word、Excel）：读取选中文本 / 单元格区域作为“引用内容”附在消息里（大小受限、显示将发送的内容并需要用户确认）；把回答“插入到光标处 / 替换选区 / 写入单元格”；不读取整篇文档，不在用户不知情时发送文档内容。
3. **清单（manifest）**：按租户生成加载项清单（XML 或统一清单）：名称、图标、窗格地址、来源域名白名单；提供下载与集中部署说明。窗格页面设置正确的 CSP / 框架来源限制。
4. 席位校验（T-151）与审计照常；页面不缓存对话到浏览器存储（只在内存）。
5. 前端：管理员端“门户设置”里增加“Office 插件”开关与清单下载（仅在开启时可下载）。

## 验收标准

- [ ] 测试：清单生成（租户域名、来源白名单）；开关关闭时窗格接口与清单下载被拒；席位校验；跨租户隔离。
- [ ] 前端：窗格在无 Office 环境（浏览器直接打开）下能给出明确提示；Office.js 调用封装在适配层并可被替换成测试桩，选区读取 / 插入有单元测试。
- [ ] 在 Microsoft 365 测试租户里的 Word 与 Excel 实际加载一次（无测试租户时如实写明）。

## 需要产品确认

- 首版只做 Word + Excel 的任务窗格，PowerPoint / Outlook 是否纳入。
- 登录方式：使用门户登录（本规格）还是 Microsoft 账号 SSO。

## 外部条件

Microsoft 365 开发者测试租户。
