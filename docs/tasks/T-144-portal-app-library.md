# T-144 员工端 AI 应用库与表单模式

**版本**：V0.4　**依赖**：T-143；表单模式另依赖 T-064（Workflow 输入 Schema）与 T-075　**PRD**：演进 PRD 5.4、11.4、15.1、15.3

## 范围

1. **可见应用（服务端判定）**：`状态 = 已上架` 且 `员工属于可见范围`（全公司；指定组织含子组织；仅管理员 = 租户管理员角色）且 `来源仍可用`。抽成服务函数 `visible_apps(db, membership)`，T-140 的下架测试、T-143 的发消息校验共用。
2. 应用库页：按名称、描述、分类搜索与筛选；推荐应用置顶；空态“管理员尚未上架应用”（演进 PRD 16.2）。
3. 进入应用：`chat` 模式进入对话（T-143）；`form` 模式按 Workflow 输入字段生成表单，提交后运行并展示结构化输出与失败状态。
4. 首页“企业 AI”选择器与应用库使用同一可见列表。
5. 最小权限（15.3）：门户应用不能扩大来源的权限；调用时同时校验员工身份与应用可见性。

## 验收标准

- [ ] 测试：可见范围三种类型（含子组织继承）、下架、来源停用后不可见；伪造应用 ID 发起调用 404；表单模式必填缺失 422。

## 需求变更（2026-11-11）

- 可见应用条件加上“持有门户席位（或租户为全员不限）”（演进 PRD 5.4 v1.1）：`visible_apps` 对无席位成员返回空，由 T-151 实现，本任务的测试需覆盖这一条。

## 完成记录（2026-11-11，Claude Sonnet 5.5）

**范围说明**：本任务**只完成了对话（chat）模式的应用库**；第 3 条里的**表单（form）模式未做**——它依赖 T-064（Workflow 输入 Schema）与 T-075（流程连接），两者都还没做，智能体来源目前只有 `chat` 模式，所以没有任何可建立的表单应用。任务保持“待验收”，请验收时按此范围判断；表单模式等 T-064 / T-075 完成后补（需要补“必填缺失 422”测试）。

**后端**（无迁移）：`GET /portal/me/app-library`（需席位；关闭“应用库”开关时 403 `portal.feature_disabled`）：按名称 / 描述 / 分类搜索、按分类筛选、推荐应用置顶，并返回该员工可见应用的全部分类（用于筛选标签，不随搜索结果变化）；`GET /portal/me/apps/{id}`（不可见 / 不存在 / 范围外都是 404）；既有 `GET /portal/me/apps` 仍是对话页的应用选择器，**不受应用库开关影响**（首页“企业 AI”选择器与应用库用同一个 `visible_apps`）。可见性仍由唯一的服务函数 `portal_service.visible_apps` 判定（已上架、范围内含子组织、来源可用、持有席位），发消息时的校验（T-143）同样使用范围判断，伪造应用 ID 发起调用 404。

**前端**：`/portal/apps` 应用库页：搜索框、分类标签、推荐标识、应用卡片、空态“管理员尚未上架应用”与无匹配提示；点击卡片进入 `/portal?app=<id>` 新对话并预选该应用（只接受自己可用的应用 ID）。中英文齐全。

**验证**：`ruff` 通过；`test_portal_chat`（新增 5 个应用库测试，共 25 个）+ `test_portal_seat_check`（共 42 个）通过。覆盖：搜索（名称 / 描述 / 分类）、分类筛选、推荐置顶、分类标签稳定、可见范围三种类型（全公司 / 指定组织含子组织 / 仅管理员）、下架后立即消失、详情接口 404、伪造应用 ID 发起调用 404、开关关闭 403 而选择器不受影响、无席位 403、空应用库。前端 `tsc` / `lint` / `i18n:check` / `style:check` / `build` 通过；浏览器（开发库员工账号）检查了应用库、无匹配、点击进入对话并预选应用、手机宽度。

**遗留**：表单模式（见上）；应用库没有“收藏 / 最近使用”；未跑全量后端测试，合并前补跑。
