# T-081 转人工与坐席工作台

**版本**：V0.3　**依赖**：T-080、T-041、T-087　**PRD**：3.8.2（OPS-010–016）、5.5 第 3 步、5.1 转人工工单状态机、5.8、PLT-081（人工转接权益）

## 范围

1. 触发（OPS-010）：Chatflow 兜底或追问上限且开启转人工（T-063 钩子）、路由兜底、内置“转人工” Skill（T-074）、护栏动作、VIP 用户（终端用户标记）、运营“人工介入”。统一入口 `request_handoff(db, conversation, reason)`；生成工单后给终端用户发送转接提示，该会话暂停自动回复（5.5 第 3 步：消息直接进入坐席工作台）。
2. 工单 `handoff_tickets`：原因、状态（等待中 / 处理中 / 已解决）、坐席、等待开始时间、SLA、结果备注。
3. 队列（OPS-011）：VIP 优先、等待时长倒序；超过租户 SLA（默认 3 分钟，可配置）标红。
4. 接入（OPS-012）：条件更新（`WHERE status='waiting'`）保证只有一人接入，后者提示「已被 {姓名} 接入」。
5. 坐席工作台（OPS-013）：对话历史、AI 生成的上下文摘要（用户诉求、已尝试的处理、转人工原因）、回复框（消息经原渠道适配器下发，并经过输出护栏）、用户信息、知识库搜索并插入答案。新消息实时推送（SSE，复用 T-002 的 Valkey 频道机制，频道 `handoff:{ticket_id}`）。
6. 转交 / 结束（OPS-014）：转给在线坐席、结束并交还 AI、结束会话；坐席状态在线 / 忙碌 / 离线（OPS-016），拥有“运营”角色的成员可接单。
7. 超时（OPS-015）：等待超过 15 分钟（可配置）向用户发送排队提示、支持留言，并触发 `handoff.requested` 升级通知（站内 + Webhook）。
8. 侧栏“转人工”页签徽标 = 等待中数量。权益：人工转接（专业版及以上）。

## 验收标准

- [ ] PostgreSQL 并发测试：两个坐席同时接入同一工单只有一个成功。
- [ ] 测试：处理中的会话不再调用模型（假模型调用计数为 0）；交还 AI 后恢复；坐席回复经过输出护栏。
