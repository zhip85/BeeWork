# T-066 多智能体协作（一层叶子智能体）

**版本**：V0.2　**依赖**：T-061　**PRD**：演进 PRD 6.2、6.4（多智能体协作）、6.7、15.2；原型“新建智能体 → 能力 → 多智能体协作”

> **2026-11-10 需求变更**：原规格的“协作组 = `agents.is_team` + 五种协作模式 + 套餐映射”作废。演进 PRD 6.7 只允许**主智能体挂载叶子智能体、一层协作**，不做多层递归，也不再区分 Router / Sequential 等模式；原“模式与套餐映射待产品确认”一并取消。

## 范围

1. 智能体“能力”中的**多智能体协作**开关（默认关）：关闭时为单智能体模式，不能挂载智能体；开启后可挂载其他智能体。存 `draft_config.multi_agent.enabled`。
2. **叶子规则**（保存草稿与发布时服务端校验）：
   - 被挂载的智能体必须已发布（有线上版本）且未停用；
   - 被挂载的智能体自身不能开启多智能体协作、不能挂载智能体（叶子）；
   - 不能挂载自己；
   - 一个智能体一旦被其他智能体挂载，就不能再开启多智能体协作（否则会形成两层），返回 409 并列出挂载它的主智能体。
3. 每个被挂载的智能体必须填写**委派描述**（何时交给它），为空则配置检查不通过。
4. 运行时：叶子智能体作为工具出现在主智能体的工具调用循环中（T-061），调用其**线上版本快照**；叶子的输入输出仍经主智能体的 OC 管线；叶子运行写子 span，深度 = 2。
5. 失效（6.7、15.2）：叶子被停用、删除、或变成非叶子后，主智能体能力页高亮“失效”，配置检查列为阻断项，发布被拒。
6. 详情页“依赖”页签显示“被哪些主智能体挂载”。

## 验收标准

- [ ] 测试：未开启协作时挂载智能体被拒；挂载草稿 / 停用 / 非叶子 / 自身被拒；被挂载的智能体开启协作 409；缺委派描述不能发布；叶子停用后主智能体发布被拒；运行时调用的是叶子线上版本而不是草稿。

## 完成记录（2026-11-12，Claude Sonnet 5.5）

**无迁移**（`draft_config.multi_agent.enabled` 在 JSON 里，默认 `false`；旧数据读取补默认值）。

**叶子规则（服务端）**：
- 能力页“多智能体协作”开关（默认关）；关闭时挂载智能体 422 `assistant.multi_agent_disabled`；开着时有挂载也不能直接关（先移除挂载）。
- 可挂载的智能体必须是**叶子**：已发布（有线上版本）、未停用、自身没有开启协作也没有挂载智能体（既看草稿也看线上快照）。不满足的挂载 422 `assistant.mount_unavailable`，提示具体原因（尚未发布 / 已停用 / 不是叶子）；不能挂载自己（422 `assistant.agent_self_mount`）；已被主智能体挂载的智能体不能开启协作（409 `assistant.multi_agent_mounted`，消息列出挂载它的主智能体，且不会保存）。
- 委派描述（`mount_settings[id].delegate`）为空 → 配置检查**阻断项** `agent.delegate_missing`；已挂载智能体失效（停用 / 删除 / 不再是叶子 / 未发布）→ 阻断项 `agent.invalid`；挂载了智能体但未开协作 → 阻断项 `agent.team_disabled`。发布以配置检查的阻断项为准，所以这些都会拒绝发布；能力页把失效挂载显示为不可用并写明原因。挂载选择器只列出当前可挂载的叶子（智能体类型随之变为“可挂载”）。依赖页签（“被哪些主智能体挂载”）沿用 T-070 的引用表，无需额外代码，已加测试。

**运行时**（`agent_teams.py`，经 T-061 的工具循环与 T-071 执行器）：叶子是主智能体的一个工具 `agent:{id}`（参数 `task`），工具描述 = 委派描述 + 叶子的名称与简介；调用时取叶子的**线上版本快照**（不是草稿），用叶子自己的提示词、知识库与工具（MCP / Skill）运行同一个回答核心（`compiler.run_agent`，从原 `execute` 阶段里抽出，主智能体行为不变），调用深度 2（叶子自己的工具调用深度 = 主智能体 + 1），**叶子不能再委派**（运行时即使快照里有智能体挂载也不会提供）；叶子不经过自己的 OC 管线，它收到的任务与返回的答案处在主智能体的管线里——答案作为工具结果经主智能体的输出规则后才给模型；一个 `leaf.<名称>` span；叶子调用的耗时计入外部耗时（不算管线开销）；取消 / 超时沿用主运行的检查。叶子失败（网关错误等）不会让主运行失败，而是把失败文字回传给主智能体。单智能体模式（未开协作）下即使还残留挂载也不提供任何智能体工具；叶子在运行中被停用 / 不再是叶子则不再提供，伪造调用被拒绝。

**验证**：`ruff` 通过；`test_agent_teams`（18 个：配置规则 11 个走真实 API 与真实发布，运行时 7 个走真实执行器、事件与 ToolInvocation 记录）+ `test_agent_runtime`、`test_runtime`、`test_assistants`、`test_open_api`、`test_versions`、`test_agents`、`test_knowledge_retrieval`、`test_portal_*`、`test_mcp`、`test_skills`、`test_tool_executor` 等 295 个通过（顺带更新了 3 处写死“可挂载类型 = kb/mcp/skill”的旧断言）。覆盖：未开协作挂载被拒、草稿 / 停用 / 非叶子 / 自身被拒、被挂载者开启协作 409、缺委派描述不能发布、叶子停用 / 删除 / 变非叶子后主智能体发布被拒、依赖页签、运行时调用的是叶子线上版本（草稿提示词不生效）、叶子自己的工具调用与不能再委派、答案经输出规则。前端 `tsc` / `lint` / `i18n:check` / `style:check` / `build` 通过；浏览器检查了能力页的协作开关（开 / 关保存正常）。
全量后端测试（`./scripts/test-postgres.sh`，一次性 PostgreSQL 库，含迁移升降级与 `alembic check`）：1040 个测试全部通过。

**未做 / 遗留**
1. **真实模型没有验证**（开发库是 mock 模型，不会发起工具调用）：叶子委派只在假模型下验证，端到端的真实多智能体对话待供应商 Key。
2. **叶子的 token 用量没有并入主运行的 `tokens_in/out`**（叶子经网关调用，网关用量仍会按 `source=leaf` 记到叶子智能体名下）；主运行页看不到叶子的 token。
3. 叶子的模型回调（Langfuse 的 LLM 子 span）没有挂到主 trace 的 callbacks 上，目前只有 `tool.agent:…` 与 `leaf.<名称>` 两层 span。
4. 在界面里：挂载了智能体的主智能体“能力页”里的叶子在被删除后只显示“已删除”，没有一键移除按钮之外的修复提示；叶子被其他主智能体引用时，叶子不能被删除（沿用既有 409），所以“叶子被删除”只会出现在数据被清理的情况。
5. 多智能体协作只做一层；路由 / 编排（T-058）、Chatflow / Workflow 作为工具（T-075）仍待后续。

## 需求变更（2026-11-12）

叶子智能体保留，只用于多智能体场景：它是 L3 的委派工具（`T-162`），**不是** L2 直达的目标，也不进入能力注册中心。
