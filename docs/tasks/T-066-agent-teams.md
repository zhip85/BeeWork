# T-066 多智能体协作（一层叶子智能体）

**版本**：V0.2　**依赖**：T-061　**PRD**：演进 PRD 6.2、6.4（多智能体协作）、6.7、15.2；原型“新建智能体 → 能力 → 多智能体协作”

> **2026-11-10 需求变更**：原规格的“协作组 = `agents.is_team` + 五种协作模式 + 套餐映射”作废。演进 PRD 6.7 只允许**主智能体挂载叶子智能体、一层协作**，不做多层递归，也不再区分 Router / Sequential 等模式；原“模式与套餐映射待产品确认”一并取消。

## 范围

1. 智能体“能力”中的**多智能体协作**开关（默认关）：关闭时为单智能体模式，不能挂载智能体；开启后可挂载其他智能体。存 `draft_config.multi_agent.enabled`。
2. **叶子规则**（保存草稿与发布时服务端校验）：
   - 被挂载的智能体必须已发布（有线上版本）且未停用；
   - 被挂载的智能体自身不能开启多智能体协作、不能挂载智能体（叶子）；
   - 不能挂载自己；
   - 一个智能体一旦被其他智能体挂载，就不能再开启多智能体协作（否则会形成两层），返回 409 并列出挂载它的主智能体。
3. 每个被挂载的智能体必须填写**委派描述**（何时交给它），为空则配置检查不通过。
4. 运行时：叶子智能体作为工具出现在主智能体的工具调用循环中（T-061），调用其**线上版本快照**；叶子的输入输出仍经主智能体的 OC 管线；叶子运行写子 span，深度 = 2。
5. 失效（6.7、15.2）：叶子被停用、删除、或变成非叶子后，主智能体能力页高亮“失效”，配置检查列为阻断项，发布被拒。
6. 详情页“依赖”页签显示“被哪些主智能体挂载”。

## 验收标准

- [ ] 测试：未开启协作时挂载智能体被拒；挂载草稿 / 停用 / 非叶子 / 自身被拒；被挂载的智能体开启协作 409；缺委派描述不能发布；叶子停用后主智能体发布被拒；运行时调用的是叶子线上版本而不是草稿。
