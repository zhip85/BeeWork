# T-012 BYOK：租户自有模型密钥

**版本**：V0.2　**依赖**：T-010、T-022、T-002　**PRD**：SET-044、SET-046、SET-047、3.9.1（自有密钥审批）、SET-071、NFR-008、8.3#11

## 目标

租户可为某个供应商添加自己的 API Key，并在各环境中选择“平台托管”或“自有密钥”；使用自有密钥的调用不扣模型点数。

## 设计（已定）

- 实现位置在 LiteLLM：每个 (自有密钥 × 使用它的平台模型) 注册一个**租户私有 deployment**，别名 `bw-{模型ID}-k-{密钥ID}`；租户环境的 team 放行列表按密钥方式选平台别名或私有别名。BeeWork 不直接调用供应商。
- `tenant_model_keys`：名称、供应商、密文（`model_secrets` 加密）、掩码（前 3 位 + •••••• + 后 4 位）、`rotated_at`、状态、`created_by`；`tenant_model_environments` 增加每个供应商的 `key_mode`（platform / byok + key_id）。
- 运行时模型别名解析集中在一个函数 `resolve_model_alias(db, tenant_id, environment, model_id)`，T-025 及之后的调用方都用它。
- 计量：T-011 汇总时，私有别名的调用记为 `billing_mode=byok`，不扣模型点数（服务费口径待确认，先只记录）。

## 范围

1. 权益：`byok`（企业版，或专业版加购“自带模型密钥”）；无权益时页面锁定（PLT-083）。
2. 添加密钥（SET-047）：保存前用该密钥经 LiteLLM 发一次校验调用（临时 deployment 或 `/v1/models`，以实测为准），失败提示「密钥无效或无权限」；受“添加或轮换自有模型密钥”审批策略约束（默认 2 级；未开通二级审批的套餐按 1 级），**审批通过前密钥不可用**。
3. 轮换：同样走审批；通过后更新所有相关私有 deployment，`rotated_at` 更新；轮换超过 180 天标记“即将过期”，并发站内通知（T-023）。
4. 删除：正在被任一环境使用时阻止（RUL-013）；删除时清理 LiteLLM 私有 deployment。
5. “设置 → 模型与环境”页：自有密钥列表（SET-046）、每个供应商的密钥方式下拉（SET-044）。
6. 审计：创建、轮换、删除、切换密钥方式；明文永不出现在响应、日志、审计、审批 diff 中（审批 diff 只放掩码）。

## 验收标准

- [ ] 契约测试：私有 deployment 的注册/删除请求体；team 放行列表随密钥方式切换。
- [ ] 测试：审批未通过时密钥不可选；使用中不可删；跨租户不可见；响应中无明文。
- [ ] `check_gateway_e2e.py` 增加 BYOK 场景（可用 `mock_response` deployment 代替真实供应商，如实记录）。

## 不在范围

- 客户自有加密密钥（企业版“加密密钥”权益，属于 T-120）。
