# T-168 L2 / L3 追踪与路由评测（扩展 T-084、T-083）

**版本**：V0.5（运行时架构 v2）　**依赖**：T-161、T-162、T-165、T-084、T-083　**PRD**：演进 PRD 23.6；原 PRD 追踪与评测章节；`architecture-runtime-v2.md`

## 目标

图的第 ⑥ 层要求全链路可观测。让“这条消息走了路径 A 还是 B、JEV 多有把握、调用了哪些能力、花了多少钱”能在追踪里看到，并能用标注集评估 L2 的准确率、校准阈值。

## 范围

1. **追踪（扩展 T-084）**：Langfuse span 约定——`l2.recall`、`l2.classify`、`l2.slots`、`path.a.<能力名>`、`l3.step.<n>`、`tool.<注册 ID>`；`runs.output.route`（T-161 的版本 2）、能力调用链（含 T-164 的步骤、T-165 的尝试次数与熔断状态）在调用追踪详情里按时间线展示；列表可按“路径 A / B”“转 B 的原因”“失败的能力”筛选；成本按路径与按能力聚合（模型点数 + 工具调用次数）。仍不展示用户原文与参数值（遵循租户的隐私设置，T-086）。
2. **路由评测（扩展 T-083）**：评测用例增加“期望的路由”（某个注册项，或“走 L3”）；评测运行逐条调用 L2（不真正执行能力，可选“执行并核对结果”），输出：路径准确率、各能力的精确率 / 召回率、混淆矩阵、置信度分布；**阈值校准表**：在不同阈值下的“直达占比 / 直达准确率 / 误直达数”，并给出建议阈值（达到目标直达准确率的最低阈值，目标默认 95%）。支持用不同的 JEV 模型各跑一遍并排对比（用于切换到专用模型前后的比较）。
3. **发布门禁**：可选——路由评测的路径准确率低于设定值时阻止发布（沿用 T-083 的门禁框架）。
4. 总览：智能体详情里的“路由概览”——最近 7 天路径 A / B 占比、平均置信度、转 B 的前几类原因。
