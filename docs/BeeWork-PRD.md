## 0. 文档说明

本文是 BeeWork 平台 V1.0 的需求细化文档，基于最终原型「BeeWork-prototype.html」生成。**原型是产品功能范围、页面与交互的主依据；本 PRD 负责补充字段、校验、权限、状态机和验收规则，不应因 PRD 漏写而删减原型中的正式业务功能。**若两者存在实质冲突，先登记差异并保留原型所表达的业务能力，再由产品决策明确最终规则；不得仅凭 PRD 未覆盖就将原型功能视为非需求。原型明确标注为演示/开发工具的内容，按 0.4 和对应章节处理。

### 0.1 适用范围与读者

| 读者 | 重点阅读 |
| --- | --- |
| 前端 | 第 2 章全局框架、第 3 章各页面的布局、字段、交互与校验 |
| 后端 | 第 3 章业务规则、第 4 章数据字典、第 5 章状态机、第 6 章权限 |

### 0.2 阅读方式

- 功能需求按「模块 → 页面 → 区域 → 字段 / 操作 → 规则」组织。
- 每个页面依次给出：入口与权限、页面布局、字段表、操作表、业务规则、异常与空态。
- 字段表列：字段、类型、必填、默认值、校验 / 说明。操作表列：操作、位置、前置条件、结果。
- 下拉选项写成「值1 / 值2」。原型中的英文枚举值（如 Active、Draft）为存储值，界面按语言显示对应中文。

### 0.4 原型使用约定

- **占位页：** 原型中部分按钮点击后进入通用「功能工作区」页面（标题为按钮文字，内容为通用的运营概览、配置与治理等）。这是原型占位，不按其内容实现；这些按钮的真实行为在本文对应章节中定义。
- **角色切换：** 原型左下角用户菜单中的「切换角色（原型演示）」只用于演示。正式产品按登录身份和 RBAC 权限决定可见菜单与操作，不提供角色切换。
- **本地数据：** 原型把数据存在浏览器本地存储中，刷新后保留。正式产品全部数据存服务端，按租户隔离。
- **演示数据：** 原型中的 Acme、Olivia Lin 等名称、数字和趋势图均为示例数据，开发时以真实接口数据替换。
- **Toast 提示：** 原型中「保存草稿」「刷新」「导出」等操作只弹出「已完成」提示。正式实现须完成真实操作，成功后再提示。

## 1. 产品概述

BeeWork 是开源的 To B 多租户 AI 智能体平台。企业在租户控制台中搭建助理，由 Agent、Chatflow、Workflow 驱动，挂载知识与能力，经编排 OC 完成安全与路由，发布到渠道并在同一平台上运营、审批和计费；BeeWork 运营方在平台运营后台管理租户、套餐、模型和平台级规则。

### 1.1 两套控制台

| 控制台 | 使用者 | 范围 | 数据边界 |
| --- | --- | --- | --- |
| 租户控制台 | 租户管理员、租户用户（构建者 / 运营） | 工作台、助理、智能体、知识、能力、编排 OC、渠道、运营、审批、设置 | 只能访问本租户数据 |
| 平台运营后台 | SaaS 平台管理员 | 平台总览、租户、运维与工单、套餐与权益、模型目录、渠道类型、Widget 模板、行业术语表、PII 规则、安全基线、操作审计 | 跨租户的管理与统计数据，看不到租户业务内容（会话、知识文档等） |

### 1.2 用户角色

| 角色 | 控制台 | 可见一级菜单 | 说明 |
| --- | --- | --- | --- |
| SaaS 平台管理员 | 平台运营后台 | 平台运营后台全部菜单 | 租户、套餐、计费、模型供给、平台定义与审计 |
| 租户管理员 | 租户控制台 | 工作台、助理、智能体、知识、能力、编排 OC、渠道、运营、审批、设置 | 完整租户控制台，含设置、成员、安全、审批与账单 |
| 租户用户 | 租户控制台 | 同租户管理员，但不显示「设置」 | 构建者 / 运营：搭建助理、智能体、知识并做运营；无租户设置权限 |

租户内部的细分角色（租户管理员、构建者、运营、只读、审计员及自定义角色）在「设置 → 角色与权限」中维护，权限矩阵见第 6 章。终端用户（与助理对话的人）不登录控制台。

### 1.3 核心概念

| 概念 | 定义 |
| --- | --- |
| 租户 | 一个签约客户，计费、隔离、合规的最小单位；有套餐、隔离等级、区域、行业包和生命周期状态 |
| 组织 | 租户内部的组织树节点（事业部、部门），资源归属于组织 |
| 助理 Assistant | 面向终端用户的 AI 应用；有身份、提示词、模型、挂载能力、OC 编排、会话体验和版本；可由一个 Agent 或团队驱动 |
| 智能体 | 三种类型：Agent（指令驱动，自主决策与工具调用）、Chatflow（多轮对话编排，保留会话状态，可中断追问）、Workflow（单次任务编排，结构化输入输出） |
| 知识 | 知识库（普通 KB / FAQ KB）、文档、FAQ；供助理和 Agent 检索 |
| 能力 | Skill（可复用的任务指令与专业能力包）、MCP（通过 MCP 服务连接工具与数据）、API 插件（连接 REST 或 GraphQL 业务接口） |
| 编排 OC | 助理的请求处理管线，分 6 个阶段：PII 规则 → 记忆 → 术语表 → 问题改写 → 路由 → 组件编排 |
| 渠道 | 渠道类型由平台定义；租户创建渠道实例，绑定一个助理和一个环境 |
| Widget（组件） | 在对话中渲染的结构化 UI；平台提供模板，租户安装到组件库，由 OC「组件编排」按渠道注入 |
| 环境 | 开发 / 预发 / 生产，配置与渠道按环境区分 |
| 规则继承 | PII 规则、术语表按「平台 → 租户 → 助手」三级继承；平台强制规则不可关闭；修改上级规则只在当前层级生成覆盖，不改变上级 |
| 审批 | 发布、能力接入、数据导出、规则变更等请求经审批流审批后生效 |
| 点数 | 统一计费单位，由模型 Token 按「每千 Token 扣点」折算 |

### 1.4 部署与隔离

| 维度 | 取值 |
| --- | --- |
| 套餐 | 标准版 Standard / 专业版 Professional / 企业版 Enterprise |
| 隔离等级 | 共享 Shared / 增强 Enhanced / 专属 Dedicated |
| 区域 | US-East / EU-West / AP-Singapore / CN-Shanghai |
| 行业包 | 保险 / 跨境电商 / 通用办公 |
| 租户状态 | 试用 / 正式 / 宽限 / 只读 / 停用 / 待删除 / 已删除 |
| 界面语言 | 简体中文（默认）/ English |

## 3. 功能需求

## 3.1 工作台

### 3.2.2 创建助理向导

入口：顶栏 / 工作台 / 助理列表的「创建助理」「新建助理」。向导以全屏弹窗呈现，小标题「新建助理」，标题「创建 AI 助理」，右上角关闭。步骤条：1 开始 → 2 基础信息与模型 → 3 能力 → 4 体验。底部固定：左侧「取消」（第 1 步）或「上一步」，右侧「保存草稿」「继续」（第 4 步为「创建助手」）。

**AST-020 第 1 步 · 开始**

- 标题「希望从哪里开始？」，说明「从空白开始，或使用已审批模板加速搭建。」
- 三个单选卡（默认「从空白开始」，选中显示对勾）：
  - 从空白开始 — 配置身份、模型、能力与安全。
  - 客户支持 — 知识检索、人工转接与标准护栏。
  - 销售副驾 — 线索筛选与个性化推荐。
- 选择模板后，后续步骤按模板预填提示词、模型、推荐挂载的能力和会话体验；模板内容来自平台模板市场已安装的模板。
- 「浏览模板市场中的全部模板」：打开模板选择弹窗，按行业筛选，展示模板名、行业、安装量、发布者；选中后回到向导并以该模板预填（原型为占位页）。

**AST-021 第 2 步 · 基础信息与模型**

| 字段 | 类型 | 必填 | 默认值 | 规则 |
| --- | --- | --- | --- | --- |
| AI 助手名称 | 单行文本 | 是 | 空，占位「保险代理人成长助手」 | 1–50 字，租户内唯一；进入本步自动聚焦 |
| 使用场景 / 简介说明 | 多行文本 | 是 | 占位「专注于帮助保险代理人提升销售技能…」 | ≤ 500 字 |
| 所属组织 | 组织树下拉 | 是 | 当前用户默认组织 | 原型未画，补充；创建后只有管理员可变更 |
| 分类 | 下拉 | 否 | 客服 | 客服 / 销售 / 内部 / 保险，可由行业包扩展；原型未画，补充 |
| 助理提示词 | 多行文本 | 是 | 默认模板（见下） | 下方显示「当前字符数：N」，上限 8,000 字 |
| AI 生成建议 | 按钮 | — | — | 按名称与使用场景调用模型生成提示词，生成中显示加载；已有内容时先确认是否覆盖。原型直接填入默认模板 |
| LLM 模型 | 下拉 | 是 | 租户默认对话模型 | 选项来自租户已启用的对话模型，显示「模型名 - 一句话说明」，如「GPT-4 - 最强综合能力，适合复杂业务场景（推荐）」「GPT-4.1 mini - 响应快、成本低」「Claude Sonnet 4 - 长上下文」 |
| 驱动方式 | 单选 + 下拉 | 否 | 不指定（助理自身提示词与模型直接应答） | 可选一个可用的 Agent 或多智能体协作组；原型仅在详情展示，补充编辑入口 |
| 默认语言 | 下拉 | 否 | 租户默认语言 | 选项来自「设置 → 企业信息 → 语言」已启用语言；原型未画，补充 |
| 可见范围 | 单选 | 否 | 仅本组织 | 仅本组织 / 指定组织 / 全部组织；原型未画，补充 |

默认提示词模板：

```markdown
# 核心身份
你是一位专业、友好的企业服务助手，具备深厚的业务知识，能够耐心细致地对待每个问题并主动提供解决方案。

## 人格特征
- 语气：专业但不生硬，友好但不随意
- 表达：清晰简洁，逻辑性强
- 态度：积极正面，解决问题导向

# 行为规范
1. 始终使用礼貌、专业的语言
2. 不讨论政治、宗教等敏感话题
3. 遇到不确定的信息时明确告知用户
```

**AST-022 第 3 步 · 能力（挂载能力选择器）**

选择器也用于详情「能力」页签的「挂载能力」弹窗。

| 区域 | 说明 |
| --- | --- |
| 左侧类型列表 | 知识库、智能体（Agent）、MCP 工具、Skill、Chatflow、工作流、API 插件；已选数量以角标显示；切换类型清空搜索 |
| 搜索 | 占位「搜索{类型名}」，匹配名称与描述 |

- 智能体、Chatflow、工作流挂载后自动成为路由目标候选（见 OC-060）。
- 本步不强制选择。

**AST-024 创建与保存规则**

- 「继续」前校验当前步必填项；第 2 步名称、使用场景、提示词任一为空时「继续」不可用。（原型未校验，以本条为准。）
- 「创建助手」：生成助理，状态「草稿」，版本 v0.1，保存名称、描述、提示词、模型、挂载选择、会话体验；自动继承租户规则库与平台基线的 PII 与术语表配置；关闭向导并在列表首位显示新助理。未填名称时（仅保存草稿场景）显示「未命名助理」。
- 「保存草稿」：任一步可用，按已填内容保存为草稿并提示「草稿已保存」，向导不关闭。
- 创建受套餐「助理数」配额限制：已达上限时「新建助理」可点，但向导第 1 步显示「已达套餐上限」并禁止创建（硬限制）或提示超额计费（软限制）。
- 关闭向导时若有未保存内容，弹窗确认放弃。

**AST-030 编辑模式**

- 入口：卡片菜单「编辑」、详情「配置路径 → 编辑」、「基础配置 → 编辑」。标题改为「编辑 AI 助理」。
- 从第 2 步开始（由「能力」相关入口进入时从第 3 步开始），字段回填当前配置；第 2 步左下角为「取消」；第 4 步主按钮为「保存」。
- 从「查看完整提示词」等提示词相关入口进入时，自动滚动并聚焦到提示词输入框。
- 保存只更新草稿配置；已发布助理的线上版本不变，需「发布更新」并审批通过后生效。

- 节点卡：类型图标、名称、状态文字（「已配置」或红色「需要设置」；注释节点显示注释内容）、序号 01/02…；选中高亮。

**节点设置（AGT-042）**

- 头部「节点设置」+ 节点类型。
- 字段标签随类型变化：注释 →「注释内容」；If / Else、循环、分类 →「条件 / 规则」；变量 →「变量赋值」；其余 →「指令 / 参数」；占位「填写此节点的处理要求…」。
- If / Else：「条件满足 →」「否则 →」两个下拉，选项为「结束」及当前节点之后的非注释节点，新增时默认都是「结束」。
- 循环：「循环起点」下拉（未选时显示「请选择前序节点」），选项为当前节点之前的非注释节点；「最大循环次数」数字 1–100，默认 3。
- 上移 / 下移：首节点不可上移，末节点不可下移。
- 删除节点：立即删除并选中第一个节点；指向被删节点的分支、循环变为未配置。

**节点完整性规则（AGT-045）**，注释节点不参与：

- 名称非空。
- 智能体 / Copilot：已选引用，引用对象为可用的 Agent 或 Workflow 且不是自身。
- 连接器：已选工具，工具为可用的 MCP / API。
- 其他类型：指令 / 条件非空。
- If / Else：两个分支目标均为「结束」或位于当前节点之后的节点。
- 循环：已选循环起点且位于当前节点之前；最大次数为 1–100 的整数。

运行时：上述分支、循环、人工审核必须真实执行（原型只保存配置并提示「分支与循环规则仅保存为配置，本原型不执行运行时跳转。」）。人工审核节点生成审批任务，审批通过后继续，驳回则终止并返回失败。

### 3.3.7 Chatflow · 调试预览

- 左侧对话窗：标题为 Chatflow 名称；「新会话」清空会话并重置中断状态；首条为开场白；未发送消息时展示推荐问题按钮，点击即发送。
- 每条回复下显示执行轨迹（经过的节点名）。触发追问时轨迹末尾显示「interrupt · 等待用户补充」，输入框占位变为「补充信息以继续…」；用户补充后从中断节点恢复。
- 右侧「会话状态」面板：状态徽标（空闲 / 已中断）、thread\_id、轮数、messages 数、记忆（范围 · 轮数）、checkpoint（开 / 关）、节点路径（按序编号的非注释节点）。
- 调试使用当前草稿配置真实执行，消耗点数，不计入运营统计。（原型为本地模拟：少于 4 个字符的输入视为信息不足，并回复「能再具体说明一下吗？例如您的订单号。」；正式版由模型判断并生成追问。）

### 3.3.8 Workflow · 输入输出

- 「输入」「输出」两张字段表，标题旁显示字段数；「添加字段」新增一行，默认名「field\_N」、类型 string、非必填。
- 列：字段名（不合规或重复时红框，提示「小写下划线，且不可重复」）、类型（string / number / boolean / object / array）、必填复选框、说明（可选）、移除；无字段时显示「暂无字段」。
- 默认字段：输入 order\_id（string，必填）、reason（string）；输出 approved（boolean，必填）、comment（string）。
- 右侧「JSON Schema」实时预览：{ input: {type: object, properties, required}, output: {…} }，字段说明写入 description。

### 3.3.9 Workflow · 触发方式

| 触发 | 默认 | 配置 |
| --- | --- | --- |

### 3.3.10 Workflow · 试运行

- 左侧「输入」：按输入字段生成表单，标签为「字段名 + 类型 + 必填 \*」；boolean 用 true / false 下拉，number 用数字框，object / array 用等宽字体输入框（占位 { } / \[ \]），其余用文本框（占位为字段说明）；无输入字段时显示「未定义输入字段」。
- 「运行」：用当前草稿配置真实执行一次（原型为「模拟运行」）。
- 右侧「运行轨迹」：成功 / 失败徽标 + 运行时间；时间线「开始 0 ms → 各节点（耗时或「跳过」）→ 结束」；成功时展示 output JSON；必填输入缺失时首个节点失败并显示「缺少 {字段}」，配置不完整时显示「配置未完成」并列出检查问题。未运行时显示「填写输入并运行，查看每个节点的执行情况。」
- 试运行消耗点数，记录在「运营 → 调用追踪」并标记为试运行。

原型说明：Chatflow「会话设置 / 调试预览」与 Workflow「输入输出 / 触发方式 / 试运行」页签在原型中点击会进入占位页，但原型源码已实现上述内容，开发以本节为准。

**文档（KNW-030）**

- 区头「文档 · 仅在当前知识库中解析、分段和索引的文件与网页。」，主按钮「上传文档」。
- 上传弹窗（原型仅 Toast「上传到：{知识库}」，补充）：两种来源——本地文件（拖拽或选择，支持 PDF、DOCX、HTML、Markdown、TXT，单文件 ≤ 50 MB，一次 ≤ 20 个）与网页 URL（每行一个，http/https）；确认后每个文件生成一条文档记录，状态「处理中」。
- 处理流程：解析 → 按知识库切片策略分段 → 用知识库向量模型生成向量 → 写入索引；成功置为「已索引」并回写分片数，失败置为「失败」并记录原因。同名文件再次上传时提示「覆盖 / 保留两者」。
- 列表字段：文档、格式（PDF / DOCX / HTML / Markdown / URL）、分片数、负责人、状态（已索引 / 处理中 / 失败 / 草稿）；状态条按状态筛选并显示计数；支持搜索。列表只显示当前知识库的文档。
- 行操作：查看详情（基本信息 + 分片预览，可逐条查看分片文本）、重新索引、下载原文件（URL 类型为打开链接）、删除（确认后从索引中移除）。原型中的「复制」对文档不适用，正式版不提供。
- 文档数量变化时同步更新知识库卡片的文档数。

**FAQ（KNW-031）**

- 区头「FAQ · 优先于文档检索命中的标准问答。」，主按钮「新建 FAQ」（原型仅 Toast「在“{知识库}”中创建 FAQ」，补充为表单弹窗）。
- 表单：问题 \*（≤ 200 字）、相似问法（标签，可多条，补充）、答案 \*（多行，≤ 2,000 字）、状态（已发布 / 草稿，默认草稿）、失效日期（可选，到期自动置为「已过期」，补充）。
- 列表字段：问题、答案（摘要）、命中（30 天）、状态（已发布 / 草稿 / 已过期）；支持搜索、状态筛选、编辑、复制、删除。只有「已发布」的 FAQ 参与检索。
- 批量导入（补充）：CSV（问题,答案,相似问法以 ; 分隔），导入前显示识别条数。

**知识库设置（KNW-032）**

- 区头「知识库设置 · 当前知识库的类型、检索与索引默认配置。」，右侧「保存」，保存成功 Toast「设置已保存」。
- 知识库类型：下拉「知识库 · 文档和 FAQ」/「FAQ 知识库 · 仅 FAQ」。切换即时生效：切到 FAQ 后 Toast「已切换为 FAQ 知识库」，切回 Toast「已切换为普通知识库」。有文档时 FAQ 选项不可选，并提示「当前有 N 个文档，不能切换为 FAQ 知识库。」；强行切换时提示「知识库中已有文档，清空文档后才能切换为 FAQ 知识库。」；无文档时提示「普通知识库没有文档时可切换为 FAQ 知识库，已有 FAQ 会保留。」
- 以下仅普通库显示：
  - 向量模型：bge-m3 / text-embedding-3-large / Cohere embed v3（正式版选项来自租户已启用的 Embedding 模型）。
  - 切片策略：Semantic（语义）/ Fixed 512 tokens / By heading（按标题）。
  - 修改向量模型或切片策略后保存，提示「需要重新索引全部文档」，确认后所有文档进入「处理中」并重建索引（补充）。
- 检索相似度阈值：滑块 + 数字框，0–1，步长 0.01，默认 0.62，「仅返回相似度达到该值的知识片段」。FAQ 库也保留该设置（用于 FAQ 语义匹配）。

## 3.6 编排 OC

编排控制（Orchestration Control，OC）是每个助理的请求处理管线，也是模型与工具调用的唯一出口网关。所有渠道消息都按下表顺序处理，配置按助理独立保存。

| 序号 | 分组 | 阶段 | 导航副标题 | 运行时作用 |
| --- | --- | --- | --- | --- |
| 1 | 输入处理 | PII 规则 | 平台 · 租户 · 助手 | 对用户输入做个人信息检测，按动作脱敏、拦截或标记；输出阶段规则在出口网关对回复再执行一次 |
| 2 | 理解与上下文 | 记忆 | 短期 · 长期 | 组装本轮上下文：最近 N 轮原文 + 按优先级注入的长期记忆文件 |
| 3 | 理解与上下文 | 术语表 | 平台 · 租户 · 助手 | 提供标准术语与别名，供改写扩展、检索同义词和回复用词统一 |
| 4 | 理解与上下文 | 问题改写 | 改写策略 | 按策略改写用户问题，改写结果用于路由和检索，原文仍保留在对话中 |
| 5 | 执行 | 路由 | 分发到已挂载智能体 / 流程 | 优先规则 → 语义自动路由 → 意图澄清 → 兜底；目标执行时可检索已挂载知识库、调用已挂载工具 |
| 6 | 输出 | 组件编排 | 按渠道注入 · 校验 · 降级 | 按渠道已发布组件清单注入系统提示词，校验模型输出的组件 JSON，按兼容矩阵降级，经输出护栏后下发 |

### 3.6.3 PII 规则

2. 叠加租户层：平台规则若有租户覆盖则用覆盖（强制规则的 enabled 固定为 true），再加上租户自建规则。
3. 助手层：开启「引用全局」时取第 2 步全部，否则只取其中的强制规则；再用助手覆盖替换并加上助手自建规则。
4. 「PII 检测」关闭时，除强制规则外全部视为停用。
5. 生效数 = 结果中 enabled 的条数。

### 3.6.5 术语表

术语三级继承：平台行业术语表 → 租户术语表 → 助手术语表。修改继承来的术语会在当前层级生成副本，不影响上级。本节为助手级，租户级见 3.10，平台级见 3.16。

- OC-030 头部：标题「助手术语表」，说明「平台行业术语表 → 租户术语表 → 助手术语表。修改继承来的术语会在当前层级生成副本，不影响上级。」
- OC-031 继承链：SaaS「行业术语表 · {租户已继承的行业名，顿号分隔；无则「未继承」} · N 条」→ 租户「{租户名}租户术语表 · x 条继承 · y 条租户级 · N 条」→ 助手「{助理名} · x 条继承 · y 条助手级（未继承时「未继承租户术语表」）· N 条生效」。
- OC-032 术语区：标题「助手术语 · 仅对当前助手生效。」，按钮「新增助手术语」；开关「继承租户术语表 · 修改继承的术语后该行变为助手级，不会更改租户术语表。」（默认开）。
- OC-033 术语表格：标准术语、别名（空为「—」）、定义、层级（平台继承 / 租户级 / 租户级 · 已修改 / 助手级 / 助手级 · 已修改）、操作（编辑；本层覆盖的行多「恢复」；删除）；空表显示「暂无术语」。

- OC-035 删除：本层自建术语直接删除（「已删除术语」）；删除继承术语或本层覆盖时，在本层记录「隐藏」标记，Toast「已从助手术语表删除，租户术语表不受影响」；存在隐藏标记时显示「本层已删除 N 条继承术语」+「全部恢复」（Toast「已恢复被删除的继承术语」）。
- OC-036 恢复：删除本层覆盖，回到上级值，Toast「已恢复为继承值」。
- OC-037 运行时：生效术语以「标准术语 + 别名」形成词典：问题改写时把命中的别名扩展为标准术语（如「SKU」→ 追加「库存单位，商品编码」），检索时作为同义词参与召回，定义在命中时注入提示词。

**运行时顺序（OC-064）**

1. 优先规则开启时，按优先级从小到大匹配启用且目标有效的规则，首条命中即路由到其固定目标；优先级相同时按创建时间。
2. 未命中时进入语义路由：由路由模型给出目标与置信度；置信度 ≥ 阈值则路由。
3. 置信度不足且意图澄清开启：发送澄清话术，用户回复后合并上下文重新路由；达到最多轮次仍不足则进入兜底。
4. 兜底：固定回复或交给默认能力。
5. 同一会话已路由到 Chatflow 且处于中断等待时，下一条消息直接交给该 Chatflow，不重新路由（补充）。
6. 路由结果（命中规则 / 模型置信度 / 澄清轮次 / 兜底）写入调用追踪。

## 3.8 运营

运营模块用于监控会话、处理转人工、标注质量、运行评测和排查调用。页面标题「运营」，说明「监控会话、评估质量并排查每一次执行。」；右上「刷新」（重新拉取当前页签数据，Toast「刷新已完成」）。五个页签：实时会话、转人工（徽标 = 等待中数量）、会话标注、评测、调用追踪。

原型说明：除「实时会话」顶部的静态示意外，各页签均为通用列表，且提供了新建 / 编辑 / 删除 / 生成示例。正式版中会话、转人工工单与调用追踪由系统生成，只读；标注与评测由用户创建。以下为正式版规则。所有数据按租户隔离，并按成员的组织 / 助理数据权限过滤。

- OPS-020 列表字段：会话、标签（正确 / 回答错误 / 不安全 / 缺少知识）、标注人、备注、状态（待处理 / 已解决）；支持搜索、状态筛选、按标签 / 助理筛选。

- OPS-022 处理：「缺少知识」可一键「生成 FAQ 草稿」到指定知识库（问题取用户原话）；「回答错误」「不安全」可「加入测试用例」；处理完成后标记已解决（补充）。
- OPS-023 标注结果计入助理概览的质量指标与工作台待办。

### 3.8.4 评测

- OPS-030 列表字段：评测任务、数据集、指标（回答准确率 / 有据性 / 安全性 / 延迟）、得分、状态（排队中 / 运行中 / 通过 / 失败）。
- OPS-031 新建评测（补充）：名称 \*、助理 \* 与版本（草稿或已发布版本）、数据集 \*（助理测试用例、上传 CSV：input, expected, type、或按标签筛选的标注会话）、指标（多选）、通过阈值（默认 85%）、评判模型（租户已启用模型）。提交后状态排队中 → 运行中 → 通过 / 失败。
- OPS-032 评测详情：总分与各指标得分、与上次评测的对比、用例明细（输入、期望、实际输出、各指标得分、失败原因、调用链接）；可导出。
- OPS-033 发布门禁：助理「发布更新」时自动跑该助理的回归测试用例，结果写入审批单的「检查」列（如「回归测试通过」「评测 92%」）；租户可配置为未通过即不可提交（补充）。
- OPS-034 评测调用消耗点数，在用量中单列为「评测」。

### 3.8.5 调用追踪

- OPS-040 列表字段：Trace ID、助理、延迟、Token 数、状态（成功 / 错误 / 慢）；筛选：助理、渠道、状态、时间范围、延迟下限、来源（线上 / 调试 / 试运行 / 评测）；支持按 Trace ID、会话 ID 精确搜索。「慢」= 端到端延迟超过 5 秒（可配置）。
- OPS-041 详情（补充）：瀑布图展示整条链路的 span——渠道接入 → PII 输入规则 → 记忆 → 术语 / 问题改写 → 路由 → 目标执行（Agent 推理、工具调用、知识检索、子智能体、工作流节点）→ 组件校验 → 输出护栏 → 下发。每个 span：名称、开始时间、耗时、状态、输入 / 输出（脱敏）、模型与输入 / 输出 Token、消耗点数、错误信息。可跳转到对应会话。
- OPS-042 保留期：追踪数据保留期跟随套餐（标准版 7 天、专业版 30 天、企业版 90 天，待确认），且不超过租户会话数据保留期。

### 3.10.10 API 与 Webhook

**API 密钥（SET-090）**：「供自有系统调用助手与数据接口；密钥仅在创建时显示一次。」

- 「创建密钥」弹窗（小标题 API，标题「创建 API 密钥」）：名称 \*、环境（开发 / 预发 / 生产，默认生产）、权限范围（chat、knowledge.read、knowledge.write、analytics.read，至少 1 项，默认 chat）；可选过期时间（补充）。

- 列表行：名称、「掩码 · 环境 · 权限」、「最近使用 {日期}」（未使用为「—」）、「吊销」（正式版增加确认，吊销后立即失效，Toast「密钥已吊销」）；空态「暂无 API 密钥」。

**Webhook（SET-091）**：「将平台事件推送到自有系统，请求带签名校验。」

- 添加端点弹窗：端点地址 \*（须匹配 https://主机.域名）、订阅事件（至少 1 项）：conversation.completed、handoff.requested、approval.updated、usage.threshold、assistant.published；添加后启用，最近推送「尚未推送」，Toast「端点已添加」；并展示一次签名密钥（补充）。
- 列表行：地址、事件列表、最近推送结果（如「200 OK · 2m」）、「测试」（发送测试事件，Toast「测试事件已发送」，刷新最近推送）、启用开关、删除；停用行置灰；空态「暂无端点」。
- 投递规则：POST JSON，Header 含事件名、投递 ID、时间戳与 HMAC-SHA256 签名；非 2xx 或 10 秒超时视为失败，按 1 / 5 / 30 分钟、之后每小时重试，最多 24 小时；连续失败 24 小时自动停用并通知；提供最近 100 次投递记录与「重发」（补充）。

| --- | --- |

## 5 状态机与业务规则

### 5.1 对象状态机

| 对象 | 状态 | 流转（触发 → 结果） |
| --- | --- | --- |
| 助理 | 草稿 / 已发布 / 已停用 | 创建 → 草稿；发布更新（审批通过或无需审批）→ 已发布并生成新版本；已发布的助理继续编辑只改草稿，状态仍为已发布；停用 → 已停用（全部渠道停止服务）；启用 → 恢复停用前状态；删除仅限草稿或已停用 |
| 智能体（Agent / Chatflow / Workflow） | 草稿 / 可用 / 已停用 | 创建、保存草稿 → 草稿（已可用的对象保存草稿不影响线上配置）；设为可用（配置检查通过）→ 可用；停用 → 已停用（引用方失效）；启用 → 可用 |

| 文档 | 草稿 / 处理中 / 已索引 / 失败 | 上传 → 处理中 → 已索引 或 失败；重新索引 → 处理中 |
| FAQ | 草稿 / 已发布 / 已过期 | 新建 → 草稿；发布 → 已发布；到达失效日期 → 已过期；修改失效日期后可重新发布 |
| 自建 Skill | 草稿（待安全检查 / 检查失败）/ 可用 / 已停用 | 上传 → 安全检查；全部通过 → 可用；任一失败 → 草稿；更换文件 → 重新检查；停用 / 启用（未通过检查不可启用） |
| MCP / API 插件 | 草稿 / 可用 / 已停用 | 保存且测试通过、至少 1 个工具 → 可用，否则草稿；停用 / 启用；健康检查失败只标记异常，不改状态 |

### 5.2 草稿、版本与发布

- RUL-001 助理：提示词、模型、挂载、OC 配置、会话体验共同组成助理配置。所有编辑只写草稿；「发布更新」（或 OC「提交审批」）按审批策略生效后，生成不可变的版本快照并替换线上版本；版本号按 vX.Y 递增。版本页签可对比与回滚，回滚即以历史快照生成新版本（同样受审批约束）。
- RUL-002 智能体：维护草稿配置与可用配置两份；引用它的助理、路由、节点始终使用可用配置；调试预览与试运行使用草稿配置。
- RUL-003 渠道：线上只读取发布快照（组件清单 + 体验配置），草稿不影响线上；生产环境渠道调用助理线上版本，开发 / 预发环境渠道调用助理最新草稿。
- RUL-004 环境：模型配置按开发 → 预发 → 生产逐级发布（SET-042）；非企业版只有生产环境。
- RUL-005 并发编辑：同一对象保存时校验 row\_version，冲突时提示「该对象已被 {姓名} 修改，请刷新后重试」，不覆盖他人修改。

### 5.3 继承与覆盖

| 对象 | 层级 | 规则 |
| --- | --- | --- |
| PII 规则 | 平台 → 租户 → 助手 | 下级编辑或切换上级规则时生成本层覆盖（from\_id 指向上级），上级不变；「恢复」删除覆盖；强制规则不可停用、可改内容；优先级助手 > 租户 > 平台；开关含义见 OC-012 |
| 术语 | 行业（可多选）→ 租户 → 助手 | 同上；另支持本层「隐藏」继承术语并「全部恢复」；租户选择继承哪些行业，助手选择是否继承租户 |
| 渠道体验 | 平台 → 租户 → 助手 → 渠道 | 逐字段合并，下级只存覆盖字段；「恢复继承」删除本层字段 |
| 模型 | 平台目录 → 租户环境启用 / 默认 → 助理 / 智能体指定 | 租户只能启用套餐与区域允许的非停用模型；助理 / 智能体 / OC 改写与路由模型只能选租户已启用模型；未指定则用环境默认 |
| 合规与安全 | 平台基线 + 区域合规 → 租户 | 租户只能在基线之上收紧（如缩短保留期、新增规则），不能放宽强制项 |
| 组件 | SaaS 模板 → 租户副本 | 复制后独立编辑；模板升版仅提示，租户手动同步 |

### 5.4 引用完整性

- RUL-010 可引用条件：挂载选择器、Agent 资源弹窗、工作流节点、路由目标、兜底默认能力只提供「可用」状态的对象（状态映射见 CAP-051）。
- RUL-011 失效展示：被引用对象删除或停用后，引用处显示红色失效（GLB-083），并计入所在对象的配置检查。含失效引用的智能体不能「设为可用」；含失效挂载或失效路由目标的助理提交发布时自动检查列为「高影响」，并要求确认。
- RUL-012 删除前提示：删除 / 停用被引用对象时列出引用方数量；从助理卸载被路由规则引用的能力时确认「这些能力被路由规则引用，卸载后规则目标将失效。继续卸载？」。
- RUL-013 不可删除：有成员的角色 / 部门、正在使用的 BYOK 密钥、默认模型、有租户使用的套餐 / 模型 / 模板、被已发布渠道使用的组件、审计与工单记录。
- RUL-014 自引用：智能体不能连接或节点引用自身；智能体之间的连接不得形成环（保存时检测，补充）；运行时嵌套调用深度 ≤ 5。

### 5.5 运行时请求处理顺序

&#91;embedded content: OC 请求处理管线 · 入口、六个阶段与出口\]

渠道接入后依次经过 OC 的六个阶段；模型与工具调用只经 AI 网关，回复在下发前再过一次输出护栏。详细顺序如下：

1. 渠道接入：校验渠道凭证（域名白名单 / SDK Key / API Key / 签名），确定租户、渠道实例、环境与终端用户。
2. 准入检查：租户状态（只读 / 停用等不服务）、助理状态、配额与 QPS、非生产环境预算硬上限。
3. 若会话处于转人工处理中，消息直接进入坐席工作台，不走 AI。
4. PII 与基线输入规则（拦截则直接返回提示）。
5. 记忆组装（短期窗口 + 长期文件按优先级注入）。
6. 术语与问题改写。
7. 路由：中断等待的 Chatflow 优先 → 优先规则 → 语义路由 → 意图澄清 → 兜底。未挂载任何可路由目标时由助理自身提示词与模型直接应答（仍可使用挂载的知识库与工具）。
8. 目标执行：知识检索（FAQ 优先，再文档向量检索）、工具 / Skill 调用、子智能体与工作流；所有模型与工具调用经 AI 网关。
9. 组件编排：解析与校验组件 JSON、按渠道模式渲染或降级。
10. 输出护栏（PII 输出规则、内容安全基线）→ 经渠道下发（流式或一次性）。
11. 异步收尾：写消息与调用追踪、扣减点数、更新会话指标、会话结束时提取记忆与计算质量分、触发 Webhook。

### 5.6 配额、计费与限流

- RUL-020 点数：模型调用按「每千 Token 扣点」扣减租户当月点数（使用自有密钥时不扣模型点数）；调试、试运行、评测同样扣点并单独统计；月初重置。加购「额外 100 万点数」叠加到当月上限。
- RUL-021 配额检查时机：创建助理（助理数）、邀请 / 恢复成员（席位）、上传文档（存储）、开始新会话（会话数）、每次模型调用（点数）、每次 API 请求（QPS）。超限处理见 PLT-084。
- RUL-022 预算：租户月度预算为软上限，仅告警；开启「达到 100% 时暂停非生产流量」后，开发与预发环境请求被拒绝并提示。
- RUL-023 账单：按自然月生成，包含套餐费、加购、软限制超额部分；账单逾期由平台手动「标记欠费（宽限）」。

## 6 权限矩阵

原型只有三种视角：SaaS 平台管理员、租户管理员、租户用户（比租户管理员少「设置」菜单）。正式版租户侧按 5 个内置角色控制，可自定义角色（SET-022）；原型「租户用户」对应构建者 / 运营 / 查看者等非管理员角色。角色范围为「组织」时只对所属组织及下级的数据生效，范围为「助理」时只对指定助理及其渠道、会话生效。

- PER-011 租户侧任何角色都不能访问平台运营后台；平台管理员不能直接读取租户业务数据（会话内容、知识文档），只能通过授权代管登录访问。
- PER-012 原型顶栏的角色切换仅为演示用途；正式版按登录账号的身份决定进入租户控制台或平台运营后台（平台后台使用独立域名与独立账号体系）。

### 8.1 术语表

| 术语 | 含义 |
| --- | --- |
| 租户 | 一个企业客户在 BeeWork 中的独立空间，有自己的子域名、数据区域、套餐与成员 |
| 组织 | 租户内的部门树节点，用于成员分组与数据权限 |
| 助理 | 面向终端用户的 AI 应用，发布到渠道对外服务 |
| Agent / 协作组 | 指令驱动、可调用工具的智能体；协作组是由多个智能体按某种协作模式组成的 Agent |
| Chatflow | 可保留会话状态、支持中断追问的多轮对话编排 |
| Workflow | 有结构化输入输出的单次任务编排，可由 API、定时或作为工具触发 |

### 8.4 原型已知问题（开发时修正）

- 未本地化的英文文案：编排 OC 页说明；审批中心的页头说明、指标、工具栏与表格；运营页说明与实时会话顶部表格；设置内容区说明「Manage the core preferences for Acme Global.」；平台总览的指标、租户健康与 AI 网关卡片；编排 OC「保存草稿 / 提交审批」按钮。
- 错误翻译：模型目录中 OpenAI 显示为「打开AI」、Azure OpenAI 显示为「Azure 打开AI」；开放范围显示「全部 plans」「企业版 only」；操作审计中「导出ed tenant data」；记忆页将 UserMemory 显示为「User记忆」；部分状态词翻译不一致（Active 在不同页面显示为「运行中」或「启用」，Success 显示为「成功率」，Enforced 显示为「已强制执行」），应按字典统一。
- 能力页 MCP / API 插件页签的搜索占位仍为「搜索Skill…」。
- 智能体编辑器中 Chatflow「会话设置 / 调试预览」与 Workflow「输入输出 / 触发方式 / 试运行」页签点击后进入占位页（外层点击拦截所致），功能以 3.3 为准。
- 占位按钮：运营「全部助理」「最近 24 小时」「打开完整调用链」；审批「对象类型」「全部组织」「最早提交优先」「审阅」；知识库「上传文档」「新建 FAQ」；企业信息「更换 Logo」。正式行为见各章节。
- 行为偏差：租户停用 / 删除在原型中立即生效（应复核后生效）；删除部门会连带删除子部门（应禁止）；渠道发布「试跑」固定显示校验通过；MCP / API 保存即为可用（应测试通过）；通用列表的知识文档 / FAQ 未按当前知识库过滤；实时会话顶部示意表与下方列表数据不一致。
- 仅属演示/开发行为（不开发）：原型中「本地配置原型」「配置原型」徽标和顶栏角色切换；案例数据页及「生成示例」「恢复默认」「填充示例数据」均为正式功能。
