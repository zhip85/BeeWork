# 运行时架构 v2：LangGraph 内核 + JEV 意图判断 + 统一能力注册中心

> 2026-11-12 产品给出的调整后架构（原图：`企业级 AI 平台 Runtime 运行架构图.pdf`）。本文把它翻译成与现有代码的对应关系，并记录由此做出的任务调整（见 [`tasks/README.md`](./tasks/README.md)“运行时架构 v2”）。需求基线：[`PRD-ai-portal-and-agent-evolution.md`](./PRD-ai-portal-and-agent-evolution.md) 第 23 章。

## 1. 分层

```
① 接入层        Web / App · 微信 / 企微 Copilot · Office 插件 · 外部 Open API
      ↓
② 网关与前置     L0 基础安全（JWT / 租户隔离 / PII 脱敏）· 上下文与记忆召回 · 术语对齐
      ↓
③ 编排内核       LangGraph 状态机
                 L2 · JEV 候选意图判断：召回候选能力 → 评估置信度
                   ├─ 路径 A：高置信度且单一 → 直达能力（跳过 Agent）
                   └─ 路径 B：低置信度 / 复杂 → L3 Agent 动态规划（ReAct，读取能力注册中心）
      ↓（共享调度）
④ 能力注册中心   Dify Workflow · Skill · MCP Tool · API Tool（在“能力”目录里管理）
                 · 子 Agent · 知识库（含 FAQ）（在各自的页面里管理）—— 同属统一能力，统一收口 Schema、权限、超时与重试策略
      ↓
⑤ 执行层         Dify Adapter · Skill Executor · MCP Client · API Executor（鉴权 / 超时 / 重试 / 审计）
      ↓
⑥ 结果整合与可观测  Langfuse：Trace · Audit · Cost
```

三条关键设计：Skill / MCP / API 并非 L3 专属（L2 可直达）；LangGraph 与 Dify 解耦（Dify 是下层黑盒流程引擎）；所有能力资产化、由注册中心统一收口，避免多个调度器冲突。

## 3. 2026-11-12 决定

- **JEV 是专门做分类的 LLM。** 开发与测试阶段先用普通 LLM 扮演；之后有了专用 API，用户可在配置里手动切换模型。所以 L2 对 JEV 只依赖一个“意图分类器”接口，模型是配置项，不写死。L2 的耗时取决于所选模型，不设硬性毫秒指标，但要有超时预算，超时直接走 L3。
- **自研画布取消**（T-062–T-065 取消，T-060 下线，T-075 去掉“本平台画布”来源）：工作流统一放在 Dify，BeeWork 只做适配与调度。
- **叶子智能体（T-066）保留**，用于多智能体场景。**子 Agent 和知识库（含 FAQ）都属于统一能力**（在注册中心里有注册项、可被召回），但它们**不在“能力”目录里注册，而是在各自独立的页面里管理**（智能体页、知识库页）；注册项只是派生出来的统一视图。
- **WhatsApp 渠道（T-045）暂缓。**

## 4. 假设（未被产品明确否定，写进了规格；如不对请指出）

1. JEV 只做分类（候选 + 置信度）；路径 A 的参数由第二步按能力的输入 Schema 抽取，抽取不全或校验不过则走 L3。
1a. 子 Agent 与知识库作为注册项参与召回；路径 A 能否直达由注册项的 `direct_enabled` 决定，默认：MCP / API / Skill / Dify = 可直达；**子 Agent = 不可直达（交给 L3 委派，可在注册中心里打开）**；**知识库 = 只有 FAQ 高分命中才直答**，其余仍由主流程的自动检索处理。意图描述与示例在注册中心视图里补充，它们所属的页面继续管理名称、说明等其他内容。
2. 路径 A 只能直达“该智能体已挂载”的能力（挂载即权限范围）；L3 的发现范围同理。
3. 低置信度直接走 L3，意图澄清不再是 L2 的默认步骤（L3 可以自己追问）。
4. 路径 A 调用的结果：Dify 的回答原样返回；MCP / API / Skill 的结果经一次不带工具的“结果整合”模型调用生成回复（能力可声明 `direct_output` 跳过整合）。
5. Skill 采用声明式“步骤 + 依赖”格式（见 T-164，格式待产品确认）。
6. 能力的“意图描述与示例”由能力管理员填写，召回与 JEV 都依赖它；没有填写时退化为名称与说明。
